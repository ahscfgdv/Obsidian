
## 主板故障

### 更换主板的SOP

#### 适用范围与前提

本 SOP 适用于 IDC 运维中**因主板硬件故障而更换服务器主板**的场景，前提是**复用原硬盘、网卡、RAID 卡等插卡**，以避免操作系统和业务数据重装。若整机替换或硬盘同时更换，则不属于本文范围。

更换主板并非简单的硬件替换。新主板的 BMC 与 BIOS 配置会恢复出厂默认，板载网卡的 MAC 地址会变更，Linux 侧的网卡命名和绑定配置也可能随之失效。SOP 的核心，是在动手之前把**可恢复的状态**完整留存，在换完之后按顺序**重建**。

---

#### 第一阶段：更换前——必须完成的记录与备份

这一阶段的每一项记录，都是更换后恢复的依据。遗漏任何一项，都可能导致更换后需要登录机房现场或重装系统。

**BMC / 带外管理配置**：登录 BMC Web 界面（iDRAC、iLO、iBMC 等），记录 **BMC IP 地址、子网掩码、默认网关、用户名**，以及 **License/Key**（如 iLO Advanced、iDRAC Enterprise）。若支持配置导出，直接导出 BMC 配置文件。

**SEL 与 FRU**：通过 `ipmitool` 导出系统事件日志和 FRU 信息。SEL 是硬件故障的历史证据，在保修索赔中可能被要求提供；FRU 记录了原主板的 **SN 和型号**，是更换后烧录或核对资产信息的基础。

```bash
ipmitool -I lanplus -H <BMC_IP> -U <用户> -f <密码文件> sel elist > sel-backup-$(date +%F).txt
ipmitool -I lanplus -H <BMC_IP> -U <用户> -f <密码文件> fru > fru-backup-$(date +%F).txt
```

**BIOS / UEFI 配置**：记录启动模式（UEFI/Legacy）、启动顺序、CPU/内存相关设置、SR-IOV 或 VT-d 等虚拟化选项。Lenovo 服务器可用 XClarity Essentials OneCLI 将系统配置保存到外部介质；Dell 的 Easy Restore 会在更换后自动提示恢复备份的 UEFI 配置。

**线缆清单与物理位置**：拔下每根线缆时**逐一记录**其连接位置（端口号、槽位号）。硬盘、网卡、HBA 卡必须**按原槽位**插入新主板或机箱，否则 Linux 网卡命名和 RAID 配置可能错位。

**固件版本基线**：记录当前 BIOS、BMC 及 CPLD 固件版本。更换主板后，新主板固件版本可能与旧板不同，需要**统一到与原环境一致的版本**，或统一升级到经过验证的最新版本，避免因固件差异引入兼容性问题。

---

#### 第二阶段：下电与硬件拆卸

**下电操作**：通过 BMC 或操作系统正常关闭主机，而非直接拔电。确认业务已迁移或停止，电源状态为 off 后再进行下一步。

**防静电**：佩戴**防静电腕带**并良好接地，去除手表、戒指等导电物体。拆下的 DIMM、CPU、PCIe 卡必须放置在**防静电台面或防静电袋**中，不可直接放在机箱外壳或普通桌面上。

**拆卸顺序（典型，以具体机型手册为准）**：断开所有外部线缆（光纤、以太网、电源）→ 卸下顶盖 → 拆除导风罩、风扇架、PCIe Riser → 拔下主板上所有内部线缆并**对照线缆清单确认无遗漏** → 依次卸下 DIMM、CPU 及散热器（注意 CPU 插槽针脚保护）、RAID 卡/网卡等插卡 → 卸下固定主板的螺丝，取出旧主板。

**CPU 与插槽保护**：拆下 CPU 时严禁触碰插槽针脚；旧主板退回前，需将新主板附带的 **CPU 插槽保护盖**安装到旧主板上，防止运输中损坏针脚。

---

#### 第三阶段：新主板安装与最小化验证

**复装复用部件**：将原 DIMM **按原槽位**插入新主板，安装 CPU 和散热器，按**线缆清单**逐根接回内部线缆，插入 PCIe 卡和 LOM 网卡。所有复用部件保持与原槽位一致。

**最小化上电验证（不接业务网络）**：先不接入业务网线，仅连接 BMC 管理口和电源，通过 BMC 远程开机。观察是否有硬件告警（POST 错误、风扇异常、内存/CPU 报错）。在确认硬件层面无异常之前，不进行 BMC 配置修改或业务网络接入，避免将硬件问题误判为配置问题。

---

#### 第四阶段：更换后配置恢复

**BMC 网络与访问恢复**：新主板 BMC 默认可能为 DHCP 或固定 IP。通过 BMC 的默认地址或本地 Console 进入，将 **BMC IP、掩码、网关**设置为与原环境一致，恢复用户账号和 **License/Key**。若更换前导出了 BMC 配置文件，优先导入；但注意导出的配置可能**不包含密码**，用户密码需要手工重设。

**SN / 服务编号**：新主板的 SN 是空白的或为新 SN，必须恢复为原 SN，否则资产系统、保修记录和监控平台会出现标识错乱。

- **Dell**：开机时 BIOS 检测到新主板和备份闪存中的旧 Service Tag，会提示 **Easy Restore**，按 `Y` 可自动恢复 Service Tag、iDRAC License 和 UEFI 配置。若 Easy Restore 不可用，进入 **System Setup → Service Tag Settings** 手工录入。
- **华为**：需使用 SmartKit 等工具将原 SN **烧录**到新主板，否则 iBMC 中 SN 显示为空。
- **其他品牌**：参照对应厂商的维护手册执行 SN 写入或恢复。

**BIOS / RAID 配置**：按更换前记录的基线恢复启动模式、启动顺序和虚拟化选项。若服务器使用硬件 RAID 卡，更换主板后 RAID 配置可能丢失，需要在 RAID 卡管理界面中**导入外部配置（Import Foreign Configuration）** ，或确认 UEFI 启动模式下是否已自动导入。

---

#### 第五阶段：操作系统内网络配置修复（关键易漏环节）

主板更换后，**板载 LOM 网卡的 MAC 地址会发生变化**。Linux 的 `udev` 和网络脚本仍绑定着旧 MAC，会导致网卡名称漂移或接口无法启动。

**清理 udev 持久化网络规则**：进入 `/etc/udev/rules.d/`，备份后删除 `50-persistent-net.rules` 或 `70-persistent-net.rules`。系统重启后会基于新 MAC 重新生成规则。

```bash
cd /etc/udev/rules.d
cp 70-persistent-net.rules 70-persistent-net.rules.bak-$(date +%F)
rm -f 50-persistent-net.rules 70-persistent-net.rules
```

**更新或注释 ifcfg 文件中的 MAC 绑定**：进入 `/etc/sysconfig/network-scripts/`，检查 `ifcfg-*` 文件中的 `HWADDR=` 或 `MACADDR=` 行。如果该值与新网卡的实际 MAC 不一致，网卡会拒绝启动。可将旧 MAC 行**注释掉**（行首加 `#`），或将其更新为 `ip a` / `ifconfig` 显示的新 MAC。

**Bonding 场景额外注意**：如果使用了 bond，除物理网卡配置外，还需检查 `ifcfg-bondX` 中的 `MACADDR` 行，同样注释或更新。部分平台（如 FusionCompute）的管理网口也可能绑定了 MAC，需一并处理。

**刷新规则并重启验证**：执行 `udevadm control --reload-rules && udevadm trigger --subsystem-match=net`，然后重启主机，确认网卡名称、IP、bond 状态与更换前一致。

---

#### 第六阶段：验证与收尾

**硬件层**：BMC 中无新增严重告警；`ipmitool sensor` 各传感器状态为 `ok`；`ipmitool sel elist` 中无与本次更换相关的未处理错误；FRU 中的 **SN 已恢复为原值**。

**带外管理层**：BMC IP 可达，Web 登录正常，用户权限和 License 状态正常；`ipmitool chassis power status` 可控。

**系统与网络层**：操作系统正常启动；`ip a` / `ip link` 显示网卡名称与更换前一致；业务 IP 可达，bond 状态正常（如 `cat /proc/net/bonding/bondX`）；关键服务进程已启动。

**业务层**：按业务清单逐项验证端口监听、应用健康检查和依赖调用。确认无误后，恢复监控告警，更新资产台账中的**主板 SN、BMC MAC（若变更）** 及维修记录，归档本次更换的 SEL、FRU 和配置备份文件。

---

#### 检查清单（速查）

| 阶段       | 必做项                                                                       |
| -------- | ------------------------------------------------------------------------- |
| 更换前      | 记录 BMC IP/网关/账号/License；导出 SEL、FRU；记录 BIOS 配置；列线缆清单；记录固件版本                |
| 拆卸       | 防静电；按清单逐一标记线缆；CPU 插槽保护；DIMM/插卡防静电存放                                       |
| 安装       | 复用部件**原槽位**；按线缆清单复接；最小化上电验证硬件                                             |
| 配置恢复     | BMC IP/账号/License 恢复；**SN 烧录或 Easy Restore**；BIOS/RAID 配置导入               |
| Linux 网络 | 删除 `*-persistent-net.rules`；注释/更新 `ifcfg` 中的 `HWADDR/MACADDR`；刷新 udev 后重启 |
| 验证       | 硬件无告警、SN 正确、网络与 bond 正常、业务逐项确认                                            |

## BMC

### 主要功能

- **远程开关机、重启、强制下电**；
    
- **KVM over IP**：远程看服务器屏幕、模拟键盘鼠标；
    
- **远程挂载虚拟光驱/ISO**，用于装系统；
    
- **硬件监控**：温度、风扇、电压、电源、硬盘/内存等传感器状态；
    
- **告警和日志**：硬件故障日志、系统事件日志；
    
- **BIOS/UEFI 配置**：部分服务器可通过 BMC 进入 BIOS 设置；
    
- **SOL/串口重定向**：远程查看串口输出；
    
- **用户权限和审计**：管理 BMC 登录账号。

不同的服务器厂商有不同的接口命名

华为 iBMC
惠普 iLO

IBM IMM

### 故障工单

- 带外网络不通

### IPMItool

#### 远程连接通用格式

远程操作 BMC/iDRAC/iLO 时，基础命令结构如下：

```bash
ipmitool -I lanplus -H <BMC_IP> -U <用户名> -P <密码> <子命令>
```

- **`-I lanplus`**：使用 IPMI v2.0 加密接口，远程操作应优先使用，而非旧的 `lan` 接口。
- **本地执行**（在服务器操作系统内）可省略 `-H/-U/-P`，直接 `sudo ipmitool <子命令>`。
- 密码不便明文传递时，可用 **`-E`** 从环境变量读取，或 **`-f <密码文件>`**。
- 部分厂商（如 HP）BMC 的 LAN 通道号可能为 **2**，其他多数为 **1**，`lan`/`user` 类命令需注意通道号差异。


#### 电源与机箱控制

| 命令 | 作用 |
|---|---|
| `ipmitool chassis power status` | 查询当前电源状态（on/off） |
| `ipmitool chassis power on` | 开机 |
| `ipmitool chassis power off` | **强制下电**（直接切断供电，非正常关机） |
| `ipmitool chassis power cycle` | **冷重启**（先下电再上电） |
| `ipmitool chassis power reset` | **热重启**（类似按 Reset 键） |
| `ipmitool chassis power soft` | 发送 ACPI 软关机信号，请求 OS 正常关闭 |
| `ipmitool chassis status` | 机箱整体状态（电源、过载、故障、前面板锁定等） |
| `ipmitool chassis identify` | 点亮/关闭前面板定位灯（默认闪烁 15 秒） |
| `ipmitool chassis restart_cause` | 查询**上一次重启的原因** |

`chassis power off` 和 `power cycle` 会直接切断主机供电，可能造成数据丢失或文件系统损坏，须在变更窗口内执行。


#### 传感器与硬件健康

| 命令 | 作用 |
|---|---|
| `ipmitool sensor` 或 `ipmitool sensor list` | 读取**所有传感器**的当前读数与阈值状态（温度、电压、风扇转速等） |
| `ipmitool sdr` 或 `ipmitool sdr list` | 输出传感器数据记录（SDR），包含传感器名称、读数、状态 |
| `ipmitool sdr get <传感器名称>` | 查看指定传感器的详细 SDR 信息 |

`ipmitool sensor` 输出中**状态列**出现 `ok` 以外的值（如 `cr` 临界、`nc` 不可恢复）时，需立即关注对应硬件。


#### SEL 系统事件日志

| 命令 | 作用 |
|---|---|
| `ipmitool sel list` | 列出 SEL 原始记录 |
| `ipmitool sel elist` | **推荐使用**，以“传感器名称 + 状态”的可读格式输出，比 `list` 更直观 |
| `ipmitool sel clear` | **清空 SEL**（执行前务必先导出备份） |
| `ipmitool sel save <文件名>` | 将 SEL 导出到文件，便于归档或厂商报修 |


#### FRU 资产信息

FRU（Field Replaceable Unit，现场可更换单元）命令用于读取硬件出厂信息，是资产盘点和保修报修时获取 **SN、型号** 的核心手段。

| 命令 | 作用 |
|---|---|
| `ipmitool fru` 或 `ipmitool fru print` | 读取所有 FRU 的清单信息，包括**序列号（SN）、产品型号、资产标签、制造商**等 |
| `ipmitool fru print <FRU_ID>` | 仅查看指定 FRU（如主板、机箱、电源）的信息，常见 ID 为 `0` 或 `1` |


#### BMC 网络配置（LAN）

| 命令 | 作用 |
|---|---|
| `ipmitool lan print <通道号>` | 查看指定 LAN 通道的 BMC 网络配置，多数为**通道 1**，HP 常为**通道 2** |
| `ipmitool lan set <通道号> ipsrc static` | 将 BMC 地址获取方式设为**静态**（也可设为 `dhcp`） |
| `ipmitool lan set <通道号> ipaddr <IP>` | 设置 BMC 的 IP 地址 |
| `ipmitool lan set <通道号> netmask <掩码>` | 设置子网掩码 |
| `ipmitool lan set <通道号> defgw ipaddr <网关>` | 设置默认网关 |

修改 BMC 网络配置需谨慎，建议在带内或本地 Console 环境下进行，避免配置错误后带外彻底失联。


#### 用户与权限管理

| 命令 | 作用 |
|---|---|
| `ipmitool user list <通道号>` | 列出 IPMI 用户及其权限级别，常用 `1` |
| `ipmitool user set name <用户ID> <用户名>` | 设置或修改用户 ID 对应的用户名 |
| `ipmitool user set password <用户ID> <新密码>` | 修改指定用户的密码 |
| `ipmitool user enable <用户ID>` / `disable <用户ID>` | 启用或禁用某个用户账号 |


#### Serial-over-LAN（SOL）远程控制台

SOL 允许通过 IPMI 网络远程访问服务器的串口控制台，在 OS 网络不通或需要查看 BIOS/启动阶段输出时非常有用。

| 命令 | 作用 |
|---|---|
| `ipmitool sol activate` | 激活 SOL 会话，进入远程串口控制台 |
| `ipmitool sol deactivate` | 终止当前 SOL 会话 |
| `ipmitool sol info` | 查看 SOL 配置参数（波特率、启用状态等） |

退出 SOL 交互会话的快捷键通常是 **`~.`**（波浪号 + 句点），具体取决于终端软件配置。


#### 启动设备与引导控制

`chassis bootdev` 设置的是一次性引导覆盖，**仅在下次重启时生效一次**，之后恢复 BIOS 中配置的原有引导顺序。

| 命令 | 作用 |
|---|---|
| `ipmitool chassis bootdev pxe` | 设置**下次启动**从 PXE 网络引导 |
| `ipmitool chassis bootdev pxe options=efiboot` | UEFI 环境下设置 PXE 引导时，需附加 `options=efiboot` |
| `ipmitool chassis bootdev disk` / `cdrom` / `bios` | 将下次引导目标设为硬盘、光驱或 BIOS 设置界面 |


#### 管理控制器（MC）自身操作

| 命令 | 作用 |
|---|---|
| `ipmitool mc info` | 查看 BMC 控制器自身信息（**固件版本**、制造商、IPMI 版本等） |
| `ipmitool mc reset cold` / `warm` | **重启 BMC 控制器**（cold 为彻底重启，warm 为热重启） |
| `ipmitool chassis selftest` | 执行 BMC 自检并输出结果 |
| `ipmitool mc getsysinfo` | 读取系统信息（部分平台支持，可获取 BIOS/BMC 版本等） |


#### 原始命令与厂商扩展

`raw` 直接发送 IPMI 字节流，用于执行标准命令未覆盖的厂商私有功能，写错参数可能触发未定义行为，仅在有明确厂商文档或脚本依据时使用。

```bash
ipmitool -I lanplus -H <IP> -U <用户> -P <密码> raw <netfn> <cmd> [data]
```

日常运维中，`raw` 常用于厂商特定的 SEL 配置、用户权限精细控制、VLAN 设置等场景，具体字节序列需参考对应 BMC 厂商的接口文档。
