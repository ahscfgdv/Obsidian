### CPU关键性能参数总览

#### 一句话定义
看懂一颗服务器CPU，就是看懂一组相互制约的参数：**核心/线程、主频、TDP、缓存、制程、内存通道、PCIe 通道、互连与路数**——它们共同决定了性能、功耗和适用场景。

#### 核心内涵
本质是"**在功耗和成本的笼子里，平衡单核速度与多核吞吐**"。核心多≠快，主频高≠强；真实表现取决于"核数 × 单核性能 × 内存/IO 是否喂得饱"，任何一环短板都会成为瓶颈。这也是为什么前面反复强调内存通道要插满、PCIe 带宽要够。

#### 关键特征
| 参数          | 含义                                  | 运维/面试要点                           |
| :---------- | :---------------------------------- | :-------------------------------- |
| 核心数 Cores   | 物理计算单元数量                            | 决定并发/多核吞吐；虚拟化、数据库看这个              |
| 线程数 Threads | 逻辑线程，靠 SMT/超线程把一个物理核当两个用            | 线程数常=核心数×2；BIOS 里 SMT 可开关         |
| 主频 Base     | 保证的基础频率                             | 稳定负载的性能基准                         |
| 睿频 Turbo    | 单核/少核短时冲刺的最高频率                      | 不能长时间维持，受功耗和温度限制                  |
| TDP         | 热设计功耗（W）                            | 决定散热与机柜供电预算；高 TDP 机型要关注制冷         |
| 缓存 L1/L2/L3 | 多级高速缓存                              | 详见 [[#缓存]]L3 越大对数据库越有利            |
| 制程          | 制造工艺（nm，如 7nm/5nm/Intel 7/Intel 3）  | 制程越先进，同功耗下性能/能效越好                 |
| 内存通道        | CPU 到内存的并行通路                        | 详见 [[#CPU内存通道]]服务器 8~12 通道，必须均衡插满 |
| 内存类型/频率     | DDR4 / DDR5，速率如 3200/4800/6000 MT/s | 4代起 Xeon 与 EPYC 9004 全面转 DDR5     |
| PCIe 通道     | 可挂接显卡、网卡、NVMe 的通道数（如 64/128 lane）   | EPYC 单路人多，GPU/高速网卡多时尤其重要          |
| 互连          | Intel UPI / AMD Infinity Fabric     | 决定多颗 CPU 之间通信带宽，影响路数与 NUMA 延迟     |
| 路数          | 单机 CPU 颗数（1S/2S/4S/8S）              | 单路 SKU（U后缀）不能当双路用                 |

#### 原理/机制
参数之间存在"木桶效应"：**主频再高，内存通道没插满或 PCIe 带宽不足，CPU 也会"饿着"**；核数再多，如果软件按单核授权或业务是单线程，也发挥不出来。所以选型和排障都要成体系地看，而不是盯一个数字。例如排查"CPU 利用率高但吞吐量上不去"，就要顺着 [[#缓存|CPU缓存]] 命中率、内存通道带宽、NUMA 跨路访问延迟这条链往下查。

#### 分类或类型
按优化方向，可把型号分为几类：
- **通用型**：核数与主频均衡（Gold 63xx、EPYC 75xx），覆盖大多数业务。
- **高主频型**：核少频高（后缀 X / Y），适合单线程敏感、按核授权的软件。
- **高密度/高核型**：核数拉满（EPYC 97X4、Xeon 6 E核、H 后缀），适合云原生、高并发。
- **特殊优化型**：网络（N）、存储（S）、大内存（M/L）、单路（U）等专用 SKU。

#### 典型例子
面试快速应答模板："看 CPU 主要看**核心线程数、主频、TDP、缓存和通道数**。核心线程定并发能力，主频定单核速度，TDP 关系到散热和供电规划，L3 缓存影响数据库性能，内存和 PCIe 通道决定数据喂不喂得饱。像机房里的金牌 6338 是 3 代 32 核、8 通道 DDR4；新一点的 4 代起步就换 DDR5 和 PCIe 5.0。扩容内存时我会按通道均衡插满，避免带宽打折。"（相关机型细节见 [[服务器]]、[[主板]]）

### 服务器CPU主要阵营

#### 一句话定义
服务器CPU市场目前由 **Intel 至强（Xeon）、AMD 霄龙（EPYC）** 两大 x86 阵营主导，以及以 **海光、鲲鹏、飞腾、龙芯、兆芯** 为代表的国产信创阵营，三者在架构授权、指令集兼容性和生态上各有路线。

#### 核心内涵
本质是"**x86 生态 + 国产化替代**"两条主线的并存。Intel/AMD 是全球化商用服务器的事实标准；国产CPU则是在信创（信息技术应用创新）背景下，为保障供应链安全而大力发展，其中海光走的是"**x86 授权兼容**"路线（迁移成本近乎为零），鲲鹏/飞腾走 ARM 路线，龙芯走完全自主的 LoongArch 指令集路线。**代码兼容性越好，客户从 Intel 迁移过来的成本越低。**

#### 关键特征
- **x86 阵营（Intel / AMD / 海光）**：生态最成熟，操作系统、中间件、软件兼容性最好。
- **ARM 阵营（鲲鹏 / 飞腾 / Ampere）**：多核高并发、能效比高，移动端生态强，但需软件重新适配编译。
- **自主指令集（龙芯 LoongArch）**：完全自主可控，生态建设仍在推进中。
- **路数（Socket）**：服务器支持单路（1S）、双路（2S）、四路（4S）、八路（8S），路数越多扩展能力越强，成本也越高。

#### 分类或类型
| 阵营 | 代表产品 | 架构/指令集 | 典型场景 |
| :-- | :-- | :-- | :-- |
| Intel | Xeon Scalable（至强可扩展）/ Xeon 6 | x86-64 | 通用企业、云、数据库，市占率最高 |
| AMD | EPYC 7001/7002/7003/9004/9005 | x86-64 (Zen) | 高并发、云计算、高核数性价比 |
| 国产 x86 | 海光 C86（三号/四号）、兆芯 | x86-64（授权） | 信创、金融、政务核心系统替代 |
| 国产 ARM | 鲲鹏 920/930、飞腾 | ARM64 | 信创、运营商、云计算节点 |
| 国产自主 | 龙芯 3A5000/3C5000 | LoongArch | 党政、关键基础设施自主可控 |

#### 典型例子
在 IDC 运维中，判断一台服务器"是什么平台"直接影响备件、内存、操作系统的选型。例如浪潮、新华三的国产信创机型常搭载海光 C86（x86 兼容，可直接跑 CentOS/麒麟 + 常见中间件），而搭载鲲鹏/飞腾的 ARM 机型则必须刷 ARM 版操作系统、ARM 版软件，二者备件与镜像**不能混用**。接工单时先看机型与CPU平台，是避免"备件买错、镜像刷错"的第一步。

### Intel Xeon 至强（型号与命名规则）

#### 一句话定义
Intel Xeon Scalable（至强可扩展处理器）是 Intel 面向服务器的主流产品线，用 **"等级 + 四位数字 + 可选后缀"** 的型号编码，把定位、代数和具体 SKU 一次性表达出来。

#### 核心内涵
型号本身就是一张"身份证"。只要会读型号，不用查手册就能大致判断这颗 CPU 处于什么档次、是哪一代、配什么平台——这是运维和采购最实用的技能。==记住口诀：**第一位看等级、第二位看代数、后两位看 SKU。**==

#### 关键特征
四个等级构成金字塔（同代中越往上越强）：

| 等级 | 第一位数字 | 定位 |
| :-- | :-- | :-- |
| 铂金 Platinum | 8 / 9 | 旗舰，核数最多、路数最高（4S/8S），HPC/AI/大数据库 |
| 金牌 Gold | 6 / 5 | 主力，性能价格平衡，出货量最大，企业/云常见 |
| 银牌 Silver | 4 | 入门双路，Web 服务、轻量虚拟化 |
| 铜牌 Bronze | 3 | 基础，核少频低，轻负载或备机 |

> 注意：==等级是"定位"不是"性能绝对值"==。跨代比较时，一颗新一代金牌反超上一代铂金很常见，因为每代核心数、内存频率、总线带宽都在涨。

#### 原理/机制
**四位数字解码（以 Gold 6338 为例）**：

- **第 1 位 = 等级**：`6` → 金牌 Gold（8/9=铂金，6/5=金牌，4=银牌，3=铜牌）
- **第 2 位 = 代数**：`3` → 第 3 代（Ice Lake）
- **第 3~4 位 = SKU 编号**：`38`，同代同等级里数字越大通常越强（不代表具体核心数）

**常见后缀**（型号末尾字母，标注特殊用途）：

| 后缀 | 含义 |
| :-- | :-- |
| H | 数据库与分析型，支持 4/8 路（如 8490H） |
| Y | 支持 Speed Select 性能配置（SST-PP） |
| N | 网络/NFV 优化 |
| T | 长生命周期 + 增强散热（电信级 NEBS） |
| M / L | 大内存支持 |
| U | 单路专用（放进双路主板会让一半平台闲置！） |
| V | 虚拟机密度优化（SaaS 云） |
| S | 存储/搜索优化 |
| + | 集成加速器（DSA/DLB/QAT/IAA） |

#### 分类或类型
**各代平台差异（代际是硬指标，决定内存/插槽/主板）**：

| 代数 | 代号 | 插槽 | 内存 | PCIe | 关键变化 |
| :-- | :-- | :-- | :-- | :-- | :-- |
| 第1代 | Skylake-SP | LGA3647 | 6通道 DDR4 | 3.0 | 初代 Scalable，铂金支持8路 |
| 第2代 | Cascade Lake | LGA3647 | 6通道 DDR4 | 3.0 | 加入 AVX-512、Optane 支持 |
| 第3代 | Ice Lake-SP | LGA4189 | 8通道 DDR4 | 4.0 | 核数大幅拉高，8通道 |
| 第4代 | Sapphire Rapids | LGA4677 | 8通道 DDR5 | 5.0 | DDR5、PCIe5.0、内置 AMX 加速器 |
| 第5代 | Emerald Rapids | LGA4677 | 8通道 DDR5 | 5.0 | 与4代同插槽，刷固件可兼容 |
| Xeon 6 | Granite Rapids(P核)/Sierra Forest(E核) | LGA7529/LGA4710 | DDR5/MRDIMM | 5.0 | 全新命名，E核单路最高288核，P核最高128核 |

> ==4代与5代同为 LGA4677，很多4代平台刷固件即可上5代；但1/2代(LGA3647)、3代(LGA4189)、Xeon 6(LGA7529) 之间插槽不同，必须换主板。==

#### 典型例子
面试官拿一颗 **Xeon Gold 6338** 问你，应能脱口而出：**金牌、第3代 Ice Lake、32核64线程、48MB L3、205W TDP、8通道 DDR4-3200、64 条 PCIe 4.0**。再比如机房里常见的 Silver 4310（银牌、3代、10核），如果工单要给它扩容内存，就要按 [[#CPU内存通道|8通道]] 均衡插满的原则操作。看到型号带 `U`（如 6448Y 以外要注意单路 SKU），要警惕它在双路主板上只能亮一颗。

### AMD EPYC 霄龙（型号与命名规则）

#### 一句话定义
AMD EPYC（霄龙）是 AMD 面向服务器的高核数产品线，型号为 **"EPYC + 四位数字"**，第一位代表代际/系列，后三位为 SKU，核心数普遍高于同价位 Intel。

#### 核心内涵
EPYC 的打法是"**用核心数和 I/O 带宽取胜**"——单路就提供 64~192 核与海量 PCIe 通道，非常适合云计算、虚拟化和高并发场景。它的代际代号都是意大利城市/天体名，记住"**数字越大代际越新**"即可。

#### 关键特征
- **片式设计（Chiplet）**：一颗 CPU 由多个小芯片（CCD）拼装，良率高、核数容易做上去。
- **I/O 优势**：单路即可提供高达 128~160 条 PCIe 5.0 通道（Intel 需双路才能接近）。
- **内存通道领先**：9004/9005 系列为 12 通道 DDR5，比同期 Intel 的 8 通道多。
- **3D V-Cache**：部分型号堆叠超大 L3（如 1152MB），对数据库、游戏、仿真提升明显。

#### 原理/机制
**型号解码（以 EPYC 7543 为例）**：

- **第 1 位 = 代际/系列**：`7` → 7003 系列（第3代 Milan），`9` → 9004/9005（第4/5代 Genoa/Turin）
- **后 3 位 = SKU**：`543`，越大越高；常见后缀 `X`（高频）、`P`（高密度/高吞吐）、`B`（双路平台）、`F`（单路优化）、`H`（液冷高功耗）

#### 分类或类型
| 系列 | 代号 | 架构 | 最高规格 | 内存/PCIe |
| :-- | :-- | :-- | :-- | :-- |
| 7001 | Naples | Zen1 | 32核 | 8通道 DDR4 / PCIe3.0 |
| 7002 | Rome | Zen2 | 64核 | 8通道 DDR4 / PCIe4.0 |
| 7003 | Milan | Zen3 | 64核 | 8通道 DDR4-3200 / PCIe4.0 |
| 9004 | Genoa | Zen4 | 96核192线程 | 12通道 DDR5-4800 / PCIe5.0（128 lane 单路） |
| 9005 | Turin | Zen5 | 192核384线程 | 12通道 DDR5-6000 / PCIe5.0（160 lane） |

> 典型型号：EPYC 7543 = 32核 2.8GHz（Milan）；7663 = 56核 2.0GHz；9565 = 72核（Turin，3.15~4.3GHz）。

#### 典型例子
当业务是云主机密集虚拟化、需要"一颗 CPU 扛起更多虚机"时，EPYC 的高核数与 12 通道内存更有优势；而当软件按**单核授权收费**（如某些数据库、Oracle）时，反而应选**核少但主频高**的 Intel 或 EPYC `X` 后缀高频型号——因为此时核数越多，授权费越贵，硬件省下的钱会被授权费吃掉。这是选型时的关键权衡。

### 国产服务器CPU（信创）

#### 一句话定义
国产服务器CPU是在信创背景下推出的自主可控处理器，其中 **海光 C86** 是 IDC 运维中最常遇到的一款——它兼容 x86-64 指令集，可平滑替代 Intel/AMD。

#### 核心内涵
海光走的是"**引进授权 + 自主迭代**"路线（基于 AMD Zen1 架构授权衍生出 C86），最大优势是**生态兼容性好、迁移成本近乎为零**：Windows、麒麟、统信及主流中间件、数据库都能直接跑。从海光二号、三号到四号（C86-4G），核心数、内存、PCIe 代际逐代追平国际主流。

#### 关键特征
- **x86 全兼容**：保留 x86-64、AVX2 等指令集，海光四号高端型号支持完整 AVX-512（对 AI/科学计算重要）。
- **国密与安全**：内置密码协处理器 CCP，支持 SM2/SM3/SM4 国密算法；CSV3 技术实现虚拟机内存实时加密。
- **代际对齐**：海光三号≈8通道 DDR4 + PCIe4.0（32核）；海光四号 C86-4G 升级到 DDR5 + PCIe5.0（最高64核128线程）。

#### 原理/机制
**海光 C86 型号解码（以 C86 7490 为例）**：`74xx` 为四号 7000 系列高端，`54xx` 为中端，`34xx` 为桌面/工控；数字越大越高。核心/线程、主频、缓存、TDP 需查对应参数表。

#### 分类或类型
**海光四号（C86-4G）部分型号参数**：

| 型号 | 核心/线程 | 基础/加速频率 | L3缓存 | TDP |
| :-- | :-- | :-- | :-- | :-- |
| 7490 | 64核128线程 | 2.7 / 3.1GHz | 256MB | 400W |
| 7480 | 64核128线程 | 2.0 / 3.0GHz | 128MB | 400W |
| 7470 | 48核96线程 | 2.6 / 3.1GHz | 256MB | 320W |
| 7450 | 32核64线程 | 2.5 / 3.0GHz | 64MB | 260W |

**其他国产路线**：鲲鹏（华为，ARM64，920/930）、飞腾（ARM64）、龙芯（LoongArch 自主指令集）、兆芯（x86 授权）。

#### 典型例子
运维中接触的双路**海光7系平台**（海光三号，单颗 32 核、8 内存通道、每 CPU 16 个 DIMM 槽），扩容内存时同样要遵守 [[#CPU内存通道|8通道均衡插满]] 原则——插 6 条能点亮但性能打折，8 条或 16 条才是满配。在信创机房做硬盘/内存更换工单时，还要注意：国产机型的 BMC 界面、SEL 日志字段、BIOS 路径与浪潮/华为 x86 机型不同，排查前先确认平台，不要照搬 x86 的经验。

### 缓存

#### 一句话定义
CPU缓存是位于中央处理器（CPU）与主存（内存）之间的一个高速小容量存储器，用于缓解CPU与内存之间巨大的速度差异。

#### 核心内涵
它的本质是“速度差的缓冲池”。如果把CPU比作极速运转的加工厂，内存是远处的仓库，缓存就是工厂车间里的临时货架。它存放CPU近期最可能用到的指令和数据，避免CPU因等待慢速内存而“停工待料”。

#### 关键特征
**速度极快**：读写延迟通常在几纳秒级，远超主存；**容量小且昂贵**：通常采用SRAM（静态随机存取存储器）制造，容量在KB到几十MB之间；**对软件透明**：由硬件全自动管理，操作系统和应用程序不需要直接干预它的读写。

#### 原理/机制
基于程序的**局部性原理**。时间局部性指刚被访问的数据大概率会被再次访问；空间局部性指相邻的数据大概率会被连续访问。当CPU需要的数据在缓存中时称为“命中”（Hit），直接读取；如果不在（Miss），则需去主存中寻找，并按特定替换算法（如LRU）将新数据块搬入缓存。

#### 分类或类型
现代服务器通常分为三级：**L1（一级缓存）**，速度最快、容量最小，分指令和数据缓存，独占于每个核心；**L2（二级缓存）**，容量稍大，同样各核心独享；**L3（三级缓存）**，容量最大，由同一CPU内的所有核心共享。

#### 典型例子
在IDC运维中，通过Linux系统执行 `lscpu` 命令查看服务器硬件信息时，能清晰看到`L1d`、`L1i`、`L2`、`L3`缓存的具体容量。当业务出现高并发导致CPU利用率飙升但吞吐量上不去时，排查应用代码是否存在不合理的指针跳跃导致L3缓存频繁未命中（Miss），是深层次性能调优的切入点。

### CPU内存通道

#### 一句话定义
**CPU内存通道**（Memory Channel）是CPU内部集成内存控制器（iMC）与内存条之间的一条**独立、并行的数据通路**，每个通道拥有独立的64位数据总线，多通道并行工作可以成倍提升CPU访问内存的总带宽。

#### 核心内涵
内存通道的本质是 **“CPU到内存的多车道高速公路”**。单通道是一条64位宽的单车道，CPU在这条路上同时只能与一组内存颗粒交换数据；多通道则是在CPU和内存之间铺设了多条并行的独立车道，数据可以分散到不同车道上同时传输，总吞吐量随车道数成比例增加。但有一个关键约束：**只有所有车道承载的“货量”（内存容量）尽可能一致时，整个路网才能高效运转**；如果部分车道空置或负载不均，整体带宽会被拉低，而不是简单“少几条车道就少一点带宽”那样线性衰减。

#### 关键特征
**通道数与位宽**：每个内存通道的数据总线宽度为64位。双通道将总线宽度从64位扩展到128位，四通道扩展到256位，以此类推。通道数由CPU型号决定，消费级桌面平台常见双通道，服务器平台则从四通道起步，主流Intel Xeon和AMD EPYC平台可支持**8通道甚至12通道**。

**带宽由通道数线性叠加**：单通道的理论带宽公式为 `数据速率 (MT/s) × 64 bit ÷ 8`。例如DDR5-4800单通道带宽约38.4 GB/s，8通道理论总带宽可达约307 GB/s。通道数翻倍，理论带宽也翻倍，前提是通道被充分利用。

**通道与内存控制器的组织关系**：以第4/5代Intel Xeon Scalable为例，CPU内部有**4个集成内存控制器（iMC）** ，每个iMC管理**2个内存通道**，合计8个通道，对应16个DIMM插槽（每通道2个插槽）。通道A/B归iMC0，C/D归iMC1，E/F归iMC2，G/H归iMC3。

#### 原理/机制
**交错（Interleaving）是通道发挥带宽的核心机制**。CPU不是把一整段连续内存只放在一个通道上，而是将**连续的物理地址轮流分散到多个通道**中。这样当CPU顺序访问内存时，请求会并行落在多个通道上同时执行，从而聚合出更高的有效带宽。但**交错集合只能在容量相同的通道之间形成**。如果通道A装了32GB、通道B只装了16GB，A和B之间无法形成完整的双通道交错，只有16GB的地址空间能享受双通道带宽，剩余16GB退化为单通道访问，整体内存子系统的性能会变得不一致甚至显著下降。

**插槽安装顺序也有硬性规则**。多数服务器平台要求：在同一通道内，优先插入**物理距离CPU最远的那个插槽（通常编号为0）**；如果单通道要插两条DIMM，则离CPU最远的插槽应放**Rank数更多**的那条。违反这些规则可能导致通道无法正确识别、频率降级或带宽损失。

**多路服务器中的NUMA约束**：每个CPU插槽管理自己名下的内存通道，构成一个NUMA节点。CPU访问自己通道上的内存（本地访问）延迟约**60–100纳秒**；跨插槽访问另一颗CPU通道上的内存，需要经过UPI/Infinity Fabric互连，延迟升至**200–300纳秒**，可能带来最高**3倍的延迟惩罚**。内存通道的本地化利用，直接决定了数据库、虚拟化等延迟敏感业务的实际表现。

#### 分类或类型
**按通道数量**：单通道、双通道（桌面/入门）、四通道、六通道、**八通道**（Intel Xeon主流，AMD EPYC前代主流）、**十二通道**（AMD EPYC 9004/9005系列）。

**按配置均衡性**：**平衡配置**（每个通道的DIMM数量、总容量、Rank数尽量一致，可实现最优交错和最高带宽）与**不平衡配置**（通道间容量或DIMM数量不一致，部分地址区间交错度降低，带宽和延迟一致性恶化）。

**按每通道DIMM数（DPC, DIMMs Per Channel）** ：1 DPC（每通道1条）通常可获得最高频率；2 DPC（每通道插满2条）容量更大，但部分平台可能需要降频以保证信号完整性。

#### 典型例子
一台**双路海光7系平台**的服务器，单颗CPU支持**8个内存通道**，每CPU对应16个插槽（每通道2槽）。如果只在单颗CPU上插**6条内存**：硬件能点亮、系统能识别，但由于**8个通道中只有6个有内存、2个通道完全空置**，通道间非对称，内存带宽会下降，部分BIOS版本甚至会告警。若双路各插3条，虽然比“6条全挤在一颗CPU上”要好，但每颗CPU仍然只利用了3/8的通道，带宽远未达满配水平。该平台的**最优配置是8条或16条**（通道满配），6条属于“能跑但性能打折”的过渡配置。

IDC运维中的直接启示是：**扩容内存时不能只看"总容量够不够"，必须同时看"通道是否被均衡填满"** 。当工单要求加装内存时，应先核对服务器平台的通道总数和插槽安装优先级，优先选择**等容量、同规格、按通道对称分布**的配置方案；如果无法做到完全均衡，应在变更记录中注明带宽损失风险，避免业务上线后才发现内存性能未达预期。

### 异构运算

#### 一句话定义
异构运算是指在一个计算系统中集成CPU、GPU、NPU或FPGA等不同架构的处理器，让它们协同工作，以应对不同类型计算任务的计算模式。

#### 核心内涵
它的本质是“让专业的芯片干专业的事”。如果把传统计算比作一家只雇了“全能型大学生”（CPU）的公司，异构运算则是公司不仅雇了大学生做统筹规划，还配备了“计算器”（GPU）专门做海量重复的数学题，“扫描仪”（NPU）专门做图像识别。通过分工，实现能效和性能的最大化。

#### 关键特征
- **架构多元化**：系统内不再只有x86或ARM的CPU，还包含专为高并发、矩阵运算设计的加速芯片。
- **软硬协同**：加速器需要特定的编程框架（如CUDA）和编译器支持，软件与硬件深度绑定。
- **高速互联**：不同芯片之间需要通过PCIe或NVLink等高速总线进行数据交互，对带宽要求极高。

#### 原理/机制
CPU擅长逻辑控制和串行标量计算；而GPU/NPU等加速器内部拥有成千上万个简单的计算核心，擅长并行处理和矩阵运算。在异构机制下，CPU作为“总指挥”，负责操作系统、网络调度和任务分发；当遇到AI推理、图像渲染等重负载计算时，CPU将任务**卸载（Offload）** 给加速器，加速器处理完再将结果传回CPU。

#### 分类或类型
- **CPU + GPU**：最主流，用于AI大模型训练、视频编解码和科学计算。
- **CPU + NPU（神经网络处理器）**：专为深度学习算法设计，常见于智能网卡或边缘计算节点。
- **CPU + FPGA（现场可编程逻辑门阵列）**：硬件逻辑可随时编程，适合低延迟的金融交易或特定网络加速。
- **CPU + ASIC（专用集成电路）**：如谷歌TPU，为特定任务定制，量产成本低、能效极高。

#### 典型例子
在IDC运维中，AI算力服务器（如搭载8块NVIDIA A100或H100 GPU的机型）就是典型的异构系统。运维人员在巡检时，除了看CPU利用率，更需要通过BMC或命令行（如 `nvidia-smi`）重点监控GPU的温度、显存占用和功耗；在排查硬件故障时，GPU的PCIe链路降速或总线报错（AER错误）是引发训练任务中断的常见原因。
