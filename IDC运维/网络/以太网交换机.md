## 以太网帧

### 以太网帧格式

![image.png](https://raw.githubusercontent.com/ahscfgdv/obsidian-images/main/test/2026/20261109093148578_2026-11-09_093148.png)

![image.png](https://raw.githubusercontent.com/ahscfgdv/obsidian-images/main/test/2026/20261109093349051_2026-11-09_093349.png)

#### 一句话定义
以太网帧格式是局域网中数据传输的基本单位，相当于网络世界里的“标准快递包装盒”，规定了数据在以太网链路上发送时的结构、顺序和规范。

#### 核心内涵
以太网帧（Ethernet Frame）的核心是**封装（Encapsulation）**。当上层网络层（如IP协议）的报文想要在物理链路上传输时，必须将其装入以太网帧的“数据载荷”区域。为了防止数据在传输中损坏或送错地方，以太网帧会在载荷的前后加上首部（Header）和尾部（Trailer），形成一段有边界、有地址、可校验的数据块。

#### 关键特征
- **地址定位**：首部包含目的MAC地址和源MAC地址（MAC地址即网卡的物理硬件地址），确保帧能送达正确的相邻设备。
- **类型标识**：包含Type/Length字段，用于告诉接收方里面的数据是什么协议（如0x0800代表IPv4）。
- **完整性校验**：尾部包含FCS（帧校验序列），利用CRC算法检查数据在物理线路上是否发生了位翻转。
- **长度限制**：标准以太网帧的载荷（MTU）通常为1500字节，整个帧长在64字节到1518字节之间。

#### 原理/机制
发送端将数据自上而下逐层封装，加上帧头和帧尾后转换为光/电信号发送；接收端（或中间的二层交换机）收到信号后，通过读取目的MAC地址决定转发端口。一旦数据到达最终目标网卡，接收端会重新计算FCS并与尾部比对，一致则剥离帧头帧尾，将载荷交还给上层，不一致则直接丢弃。

#### 分类或类型
- **Ethernet II**：当前TCP/IP网络中最主流的帧格式，Type字段大于0x0600，直接承载上层协议。
- **IEEE 802.3**：传统格式，Length字段小于等于0x05DC，包含LLC（逻辑链路控制）子层。
- **802.1Q**：在标准帧的源MAC后插入4字节的VLAN标签（Tag），用于实现虚拟局域网的隔离。

#### 典型例子
在IDC运维中使用抓包工具（如Wireshark）时，看到一个标准的Ethernet II帧，展开后能看到Destination（目的MAC）、Source（源MAC）、Type（如IPv4）以及Padding（填充）和Frame Check Sequence（FCS）。


### Mac地址

#### 一句话定义
MAC地址是固化在网卡上的物理硬件地址，相当于网络设备的“身份证号”，用于在局域网（二层网络）中唯一标识一个网络接口。

#### 核心内涵
MAC（Media Access Control，媒体访问控制）地址是数据链路层（OSI第二层）寻址的基础。局域网内的交换机依靠它来识别数据帧的源和目的，从而决定将数据从哪个物理端口转发出去。

#### 关键特征
- **长度固定**：由48位二进制数（6个字节）组成。
- **全球唯一**：理论上由IEEE（电气和电子工程师协会）统一分配，确保不重复。
- **书写格式**：通常表示为12位十六进制数，如 `00:1A:2B:3C:4D:5E`。
- **结构划分**：前24位是OUI（组织唯一标识符，代表厂商），后24位由厂商自行分配给具体网卡。

#### 原理/机制
当设备发送数据时，会在以太网帧头填入目的MAC和源MAC。交换机收到帧后，会学习源MAC与接收端口的对应关系并生成MAC地址表。后续若收到发往某已知MAC的帧，交换机直接精确转发；若未知，则向除接收口外的所有端口广播泛洪。

#### 分类或类型
- **单播MAC**：第一字节最低位为0，指向单一的网卡（最常见）。
- **组播MAC**：第一字节最低位为1，指向局域网内的一组特定设备（如`01:00:5E`开头的IPv4组播映射）。
- **广播MAC**：全F（`FF:FF:FF:FF:FF:FF`），指向同一广播域内的所有设备。

#### 典型例子
IDC机房中一台服务器的网卡MAC是 `AC:1F:6B:00:11:22`，其中 `AC:1F:6B` 代表该网卡制造商的OUI。运维人员在配置DHCP静态IP绑定，或排查交换机端口下的MAC漂移时，都会直接操作这一标识。

### CRC循环冗余码检验

#### 一句话定义
CRC（循环冗余校验）是一种通过数学运算生成简短“校验码”的差错检测技术，用于判断数据在传输或存储过程中是否发生了损坏或篡改。

#### 核心内涵
它的本质是给数据附加一段数字指纹。发送方利用特定算法对数据计算出一个校验值，接收方收到数据后重新计算，如果两次结果一致则认为数据完整，不一致则直接丢弃数据。

#### 关键特征
- **检错能力强**：对突发性错误（连续多位出错）的检测率极高。
- **极低的实现成本**：主要依靠硬件电路（移位寄存器和异或门）进行位移和异或操作，速度极快。
- **无纠错能力**：CRC只能告诉你“数据坏了”，但不知道具体坏在哪一位，无法像内存的ECC那样自动修复。

#### 原理/机制
打个比方，CRC就像是用一个约定的除数去“除”数据，看余数是多少。发送方把原始数据除以一个特定的“生成多项式”（约定的除数），得到的**余数**就是CRC校验码，并将其附在数据尾部一起发送。接收方收到后，用整个数据（含校验码）再次除以同一个生成多项式，如果余数为0，则证明数据完好；如果不为0，则说明数据传坏了。

#### 分类或类型
按生成多项式长度和算法差异，常见的有：
- **CRC-32**：最常见的标准，用于以太网帧校验。
- **CRC-16**：常用于串口通信（如Modbus协议）。
- **CRC-8**：用于简单的短报文校验。

#### 典型例子
在IDC运维中，最经典的例子就是**以太网帧尾部的FCS（帧校验序列）**。以太网使用CRC-32算法生成这个4字节（32位）的FCS。当交换机收到一个网线传过来的数据帧时，底层硬件会立刻计算CRC，如果算出的值跟帧尾的FCS对不上（比如因为光衰或电磁干扰导致信号错误），交换机会直接把这个坏帧丢弃。

## 链路

### VLAN

#### 一句话定义
VLAN（Virtual Local Area Network，虚拟局域网）是一种在物理局域网上，通过逻辑划分将不同设备隔离成多个独立**广播域（Broadcast Domain）**的技术，使得物理位置不受限制的设备可以像在同一个局域网内一样通信。

#### 核心内涵
VLAN的本质是**“在物理网络上切出逻辑的独立空间”**。在传统网络中，一台交换机连接的所有设备默认在同一个广播域（即一个物理局域网），任何一台设备发出的广播包，都会发给所有其他设备。
**类比**：一台物理交换机就像一个大礼堂，所有人都在里面扯着嗓子喊（广播），非常嘈杂。VLAN技术就像在礼堂里建了多道隔音的玻璃墙，把人分进不同的房间（VLAN 10、VLAN 20）。房间内的人可以正常交流，但房间之间的广播会被墙完全挡住，互不干扰，极大地提升了“沟通效率”（网络性能）和“隐私性”（安全性）。

#### 关键特征
- **隔离广播域**：同一个 VLAN 内部可以自由广播，不同 VLAN 之间默认绝对隔离，限制了广播风暴的蔓延。
- **物理位置无关**：不论设备插在哪台交换机的哪个端口上，只要逻辑上划分到同一 VLAN，就属于同一逻辑网络。
- **增强安全性**：不同部门的敏感数据划入不同 VLAN，默认无法直接互访，需经过三层路由策略控制。
- **灵活性与成本**：无需重新布线或增加物理设备，仅通过软件配置即可调整网络拓扑。

#### 原理/机制
VLAN 的核心实现依赖于 **IEEE 802.1Q 标签（Tag）** 和交换机的端口转发规则：
- **802.1Q 标签**：当一个以太网帧在交换机之间传输时，会在源 MAC 地址和类型字段之间插入 4 个字节的标签，里面包含 VLAN ID（VID，范围 1–4094），用来标识这个帧属于哪个虚拟网络。
- **Access 端口**：连接终端设备（如服务器、PC）的端口。收包时，交换机把无标签的帧打上该端口的 VLAN ID；发包时，剥离标签，只把无标签的帧交给终端。
- **Trunk 端口**：连接交换机与交换机的端口。允许多个 VLAN 的帧通过，收包时通过标签区分属于哪个 VLAN，发包时带着标签发送。只有带标签的帧才能通过 Trunk 链路跨越物理设备。

#### 分类或类型
按划分方式，VLAN 主要分为以下几类（IDC 中最常用的是基于端口的划分）：
- **基于端口（Port-based）**：把某个物理端口固定分配给某个 VLAN。配置最简单，但设备换端口时需要重配。
- **基于 MAC 地址**：根据设备的 MAC 地址自动划分 VLAN，移动设备位置无需重配，但维护复杂，安全性弱。
- **基于子网/IP 地址**：根据设备的 IP 子网映射到 VLAN，灵活性高，但增加了交换机处理负担。
- **基于协议**：根据网络层的协议类型（如 IPv4、IPv6）划分。

#### 典型例子
在 IDC 运维中，一台 TOR 交换机下挂多个客户服务器。
1. **多租户隔离**：服务器A 属于租户A（分配到 VLAN 10），服务器B 属于租户B（分配到 VLAN 20）。交换机上的 VLAN 表确保 A 和 B 的广播包完全隔离，防止客户之间窥探数据。
2. **管理网络隔离**：交换机自身的管理 IP 配在 VLAN 99（管理网段），业务服务器放在 VLAN 100（业务网段）。运维人员可以从管理网段直接管理交换机，但即便业务服务器中毒，也不会直接影响管理网段的通道。
3. **排障点**：当服务器插上网线却不通时，首先检查交换机接口是否划分到了正确的 VLAN（`display vlan`）；如果是跨交换机通信，需要检查中间互联的 **Trunk 端口** 是否允许了该 VLAN 通过（Allowed VLAN 列表），漏放行该 VLAN 是导致故障的极常见原因。
### VXLAN

#### 一句话定义
VXLAN（Virtual eXtensible Local Area Network，虚拟可扩展局域网）是一种**在三层（L3）物理网络之上叠加二层（L2）虚拟网络的隧道封装技术**，通过将原始以太网帧封装进UDP报文，实现跨三层网络边界的二层连通性扩展。

#### 核心内涵
VXLAN的本质是 **“用三层网络搬运二层帧”**。传统二层网络的广播域受限于物理位置，VLAN ID仅12比特（最多4094个），无法支撑云数据中心成千上万的租户隔离需求。VXLAN将虚拟机发出的原始以太网帧（L2）整体作为“货物”，装入UDP/IP的“集装箱”中，通过底层IP网络（Underlay）路由到远端，再解封装还原出原始帧。虚拟机全程感知不到封装过程，仿佛仍然连接在同一台物理交换机上。

#### 关键特征
- **24位VNI**：VXLAN网络标识符（VNI）从VLAN的12位扩展到24位，支持约**1600万个**独立虚拟网段，彻底解决租户隔离的标识瓶颈。
- **L2 over L3**：虚拟机的二层帧可跨越三层路由边界传输，使不同机架、不同数据中心的虚拟机保持在同一个二层域内。
- **VTEP封装/解封装**：VXLAN隧道端点（VTEP）是执行封装的边缘实体，仅边缘设备感知VXLAN，中间网络设备只需按普通IP包转发，部署成本低。
- **无状态隧道**：每个帧独立按规则封装，隧道本身不维护会话状态，简化了转发逻辑。

#### 原理/机制
发送方虚拟机发出普通以太网帧 → 本地VTEP查表确定该帧所属VNI及目的VTEP IP → 在原始帧前依次添加**VXLAN头（含VNI）、UDP头、外层IP头和外层MAC头** → 封装后的UDP包经Underlay IP网络路由至目的VTEP。目的VTEP收到后校验VNI有效性，剥离外层封装，将原始帧交付给同VNI下的目标虚拟机。VNI实现了租户间流量的严格隔离——不同VNI的MAC地址可以重叠，但流量绝不会“串线”。

#### 分类或类型
按**VTEP的部署位置**分为三种模式：**硬件模式**（VTEP全部在物理交换机上，封装在硬件完成）；**软件模式**（VTEP全部在服务器的虚拟交换机vSwitch上，由Hypervisor完成封装）；**混合模式**（部分在vSwitch、部分在物理设备上）。在云数据中心中，软件VTEP因部署灵活最为常见；在大型物理网络骨干中，硬件VTEP可提供线速封装性能。

#### 典型例子
在IDC云平台中，租户A的VM-A1与VM-A2位于不同机架的物理服务器上，但被分配了同一个VNI（如5000）。VM-A1发出的帧经本机vSwitch（软件VTEP）封装为VXLAN UDP包，外层源/目的IP分别为两台服务器的VTEP地址，穿越Spine-Leaf三层Underlay网络后，由VM-A2所在服务器的VTEP解封装并交付。租户B的VM即使使用完全相同的MAC地址，只要VNI不同（如5001），两者流量在逻辑上永不相交。运维人员在排查VXLAN连通性时，需关注**VTEP地址可达性、VNI映射一致性、以及Underlay路由**三个层面——任何一个环节断裂，封装后的UDP包都无法完成端到端传递。

### 生成树协议

#### 一句话定义

IEEE 802.1定义的生成树协议（Spanning Tree Protocol, STP）是一套用于在**存在物理环路的二层交换网络中，通过逻辑阻塞冗余链路，构建出一棵无环转发树的协议族**，旨在防止广播风暴，同时保留链路的冗余备份能力。

#### 核心内涵

二层以太网帧没有TTL（生存时间）字段，一旦网络中存在物理环路，广播帧就会在环路中无限循环，迅速耗尽带宽与交换机CPU，形成“广播风暴”。生成树协议的核心内涵是**用逻辑手段解决物理冗余的矛盾**：允许你为了可靠性而物理上连接冗余线缆，但通过运行STP，交换机们会协商出一个无环的树形拓扑，将多余端口逻辑阻塞（Block），只保留一条活动通路。一旦活动链路故障，被阻塞的备用端口会被自动激活，恢复连通性。

#### 关键特征

- **无环拓扑**：通过分布式计算，确保任意两台交换机之间只有一条活动路径。
- **冗余备份**：被阻塞的端口并非“损坏”，而是处于待命状态，故障时可快速切换。
- **BPDU交互**：交换机之间通过交换**桥协议数据单元（BPDU）** 来交换拓扑信息、选举角色并检测故障。BPDU是STP的“通信语言”。
- **标准演进**：IEEE 802.1先后定义了STP（802.1D）、RSTP（802.1w）和MSTP（802.1s）三个版本，在收敛速度和灵活性上逐步提升。

**便于记忆**
- **802.1D**：**D** 联想为 **Delay（延迟）** 或 **Default（默认/老大哥）**。因为传统STP收敛极慢（几十秒），是默认的老一代协议。
- **802.1w**：**w** 联想为 **wait less（少等待）**。因为RSTP（快速生成树）引入了握手机制，收敛速度提升到了秒级以内，不用再苦等了。
- **802.1s**：**s** 联想为 **share（共享）** 或 **split（分流）**。因为MSTP（多生成树）把多个VLAN映射到不同实例，既能让VLAN共享实例，又能实现不同实例的链路负载分担（分流）。

#### 原理/机制

STP的核心是一个**三步选举与状态收敛**的过程，遵循“数值越小越优”的原则。

**第一步：选举根桥（Root Bridge）**。网络中所有交换机最初都宣告自己是根桥。它们比较**桥ID（Bridge ID）**，桥ID由“优先级 + MAC地址”构成，**桥ID最小的交换机胜出，成为整棵树的根**。根桥是所有路径的汇聚点，通常应手动将核心交换机优先级调低，确保其成为根桥。

**第二步：选举根端口（Root Port）与指定端口（Designated Port）**。每台非根交换机必须选出一个**根端口**，即通往根桥路径开销（Cost）最小的端口。每条网段（两台交换机之间的链路）必须选出一个**指定端口**，负责向该网段转发流量。既不是根端口也不是指定端口的端口，被置为**阻塞状态**，逻辑上断开，从而打破环路。

**第三步：状态收敛**。传统STP（802.1D）的端口从阻塞到转发需要经历Listening和Learning状态，等待定时器（约30-50秒），收敛极慢。这是IDC运维中STP被诟病的主要原因。

#### 分类或类型

IEEE 802.1的生成树协议经历了三代演进，核心差异在于**收敛速度**与**对VLAN流量的支持能力**。

- **STP（IEEE 802.1D）** ：基础版本。所有VLAN共享一棵生成树，收敛速度最慢（30-50秒），配置简单但已不适合现代高可用网络。
- **RSTP（IEEE 802.1w，快速生成树）** ：核心改进是**快速收敛**。引入了**边缘端口（直接连接终端，不参与STP计算，即插即用）** 和**P/A（Proposal/Agreement）握手机制**，在点对点链路上可将收敛时间缩短至1秒以内。但它仍然让所有VLAN共享一棵树，无法实现按VLAN的负载分担。
- **MSTP（IEEE 802.1s，多生成树）** ：当前IDC的主流选择。它将多个VLAN映射到一个**实例（Instance/MSTI）** ，每个实例独立运行一棵生成树。通过将不同的VLAN映射到不同的实例，可以让部分VLAN的流量走链路A，另一部分VLAN的流量走链路B，**在实现冗余的同时，真正做到了负载分担**，弥补了STP/RSTP的缺陷。

> **补充说明**：思科私有的PVST/PVST+是“每VLAN一棵树”，能实现负载分担，但在大规模VLAN环境下BPDU开销和CPU负担极重；MSTP正是为了以更低的资源开销实现同等甚至更好的负载分担而设计的标准方案。

#### 典型例子

在IDC运维中，生成树协议是接入层与汇聚层之间防环的“安全网”。一个典型场景是：运维人员为“增加冗余”在接入交换机和核心交换机之间多连了一根网线，若未启用STP，插上瞬间就会引发广播风暴，交换机CPU飙高、全网卡顿。启用STP（通常推荐RSTP/MSTP）后，其中一条链路会被自动阻塞，只留一条活动，冗余性得以保留而环路被消除。

日常运维中需要关注几个关键点：**根桥规划**——应手动将汇聚/核心交换机优先级设为最低（如4096），确保STP计算的可预测性，避免低性能接入交换机意外成为根桥；**边缘端口与BPDU防护**——连接服务器或终端的接入口应配置为**边缘端口（PortFast）** 以跳过监听学习阶段，同时开启**BPDU Guard**，一旦该端口收到BPDU报文（意味着可能有人私接了交换机形成环路），立即将其关闭，保护全网安全。若发现**MAC地址表频繁漂移**（同一MAC出现在多个端口），往往是STP未生效或配置错误的早期信号，需及时排查链路状态和BPDU收发情况。


#### 总结

生成树协议是二层交换网络的基石性防环机制。从STP到RSTP再到MSTP，演进的主线是**更快的收敛**与**更精细的流量控制（负载分担）** 。在IDC运维中，理解根桥选举与端口角色是排障的基础，而正确配置**根桥优先级、边缘端口与BPDU防护**，是确保接入层冗余而不引入环路风险的关键实践。

## 虚拟交换机

如ESXi上有的虚拟交换机

#### 概念定义

**虚拟交换机（vSwitch，Virtual Switch）** 是运行在服务器**虚拟化层（Hypervisor）** 上的**纯软件实现的二层交换机**。它的作用与物理交换机类似，负责在同一台物理服务器内的多个虚拟机（VM）之间，以及虚拟机与外部物理网络之间，进行数据帧的转发和隔离。

在IDC和云数据中心里，物理服务器通过网线连接物理交换机，而服务器内部成百上千台虚拟机，则通过虚拟交换机“连接”在一起。

#### 核心组成与连接关系

一个典型的虚拟交换机通常连接着三类对象：
- **虚拟网卡（vNIC）**：虚拟机内部的网卡。
- **上行链路（Uplink / pNIC）**：服务器上真实的物理网卡，用于将内部流量送出服务器，连接外部物理交换机。
- **虚拟端口/端口组（Port / Port Group）**：相当于物理交换机的接口，用于绑定虚拟网卡，并集中配置VLAN、安全策略等。

#### 主要功能

- **二层转发**：根据虚拟机的MAC地址，在内部直接转发数据帧，不消耗物理交换机的背板带宽。
- **VLAN隔离**：支持802.1Q VLAN，可以给不同虚拟机的端口分配不同VLAN，实现多租户或业务隔离。
- **策略控制**：可以配置安全组、ACL、端口镜像、流量限速（QoS）等，比物理交换机配置更灵活。
- **链路聚合**：将多块物理网卡绑定为上行链路，提供带宽扩展和冗余。

#### 与物理交换机的核心区别

| 对比维度 | 物理交换机 | 虚拟交换机 |
| :--- | :--- | :--- |
| **形态** | 硬件设备 | 软件模块（运行在Hypervisor内） |
| **端口** | 物理网口 | 虚拟端口（vPort） |
| **配置方式** | Console/SSH/网管 | 虚拟化管理平台（如vCenter、OpenStack、FusionCompute） |
| **性能** | 硬件ASIC线速转发 | 依赖CPU计算或网卡硬件加速（如SR-IOV、OVS） |

#### IDC运维中的常见应用

- **VMware环境**：vSphere标准交换机（vSS）和分布式交换机（vDS）。
- **开源云环境**：Open vSwitch（OVS），广泛用于OpenStack、Kubernetes（如OVN）。
- **私有云/华为系**：FusionCompute中的虚拟交换机。

**一句话总结：虚拟交换机就是跑在服务器软件里的一台“看不见的二层交换机”，它把虚拟机连起来，再把流量交给物理网卡送出去，是服务器虚拟化和云网络的基础组件。**

## 实操
### 如何通过console口连接交换机

通过Console口连接华为交换机，核心是**三步**：正确连接线缆、让电脑识别出COM口、在终端软件中选中该COM口并匹配通信参数。

#### 🔌 第一步：硬件连接与线缆确认

华为交换机的Console口通常是**RJ-45接口**，电脑端则可能是**DB9串口**或**USB口**。

- **线缆类型**：必须使用**Console专用线**（通常是RJ-45转DB9或RJ-45转USB的反序线），**不能用普通的以太网直通网线**替代。
- **连接方式**：
    - 若电脑有DB9串口：直接将Console线的DB9端插入电脑串口，RJ-45端插入交换机标有 `CONSOLE` 或 `CON` 的端口。
    - 若电脑无串口（笔记本常见）：需使用**USB转串口线**（如USB转RJ45或USB转DB9）。将USB端插入电脑，RJ-45端插入交换机。
- **操作建议**：部分资料建议**先关闭交换机电源，连接好线缆后再上电**，以避免热插拔可能引发的通信异常。

#### 💻 第二步：安装驱动，找到对应的COM口

这是最关键的一步，电脑必须正确识别出USB转串口设备，并分配一个COM端口号。

1. **安装驱动**：USB转串口线通常需要驱动。常见芯片型号包括 **CH340、CP2102、FTDI、PL2303** 等，需根据线缆芯片安装对应官方驱动。
2. **在设备管理器中确认COM口**：
    - 右键“此电脑” → “管理” → “设备管理器”。
    - 展开 **“端口 (COM 和 LPT)”** 选项。
    - 查看是否出现类似 **“USB-SERIAL CH340 (COM3)”** 或 **“Prolific USB-to-Serial Comm Port (COM5)”** 的设备，**记下括号内的COM号（如COM3、COM5）**。
    - 如果设备显示为“未知设备”或带有**黄色感叹号**，说明驱动未正确安装，需要重新安装驱动。

#### ⚙️ 第三步：配置终端软件（以PuTTY为例）

打开PuTTY、SecureCRT、Xshell等终端软件，新建一个**Serial（串口）** 连接。

- **端口（Port/Serial line）**：**手动选择**或填入你在设备管理器中记下的**COM端口号**（如 `COM3`）。**不要依赖“自动检测”**，必须手动指定。
- **通信参数**：必须与交换机Console口的缺省值严格一致，否则会出现乱码或无响应。

| 参数                        | 要求值                                      |
| :------------------------ | :--------------------------------------- |
| **波特率 (Speed/Baud rate)** | **9600**（绝大多数情况；部分新型号可能默认115200，可先试9600） |
| **数据位 (Data bits)**       | **8**                                    |
| **停止位 (Stop bits)**       | **1**                                    |
| **校验位 (Parity)**          | **None（无）**                              |
| **流控 (Flow control)**     | **None（无）**                              |

### 配置

#### 华为交换机基础配置命令汇总

以下脚本按“**时区时间 → 设备名 → 管理IP → 远程登录 → 保存**”的顺序编排，所有命令均不含设备提示符，可逐条复制执行；交互式命令需按提示输入。

```bash
# ============================================================
# 华为交换机基础配置脚本
# 说明：示例中的时区名、时间、设备名、VLAN、IP、端口、用户名和密码
#       请根据实际环境替换。执行顺序不建议随意调整。
# ============================================================

# ---------- 1. 进入系统视图 ----------
system-view

# ---------- 2. 配置时区（东八区，时区名 BJ 可自定义） ----------
# clock timezone 可在系统视图或用户视图执行
clock timezone BJ add 08:00:00

# ---------- 3. 退出到用户视图，设置当前时间 ----------
# 格式：HH:MM:SS YYYY-MM-DD
# 必须先设时区再设时间，否则该时间会按 UTC 处理
quit
clock datetime 14:30:00 2026-11-06

# ---------- 4. 重新进入系统视图，修改设备名称 ----------
system-view
sysname SW-Core-01

# ---------- 5. 创建管理 VLAN（示例 VLAN 99） ----------
vlan 99
quit

# ---------- 6. 配置 VLANIF 管理 IP（示例 192.168.99.10/24） ----------
interface vlanif 99
ip address 192.168.99.10 24
quit

# ---------- 7. 将管理物理端口加入管理 VLAN（示例 G0/0/1） ----------
# 端口号请按实际连接修改
interface GigabitEthernet 0/0/1
port link-type access
port default vlan 99
quit

# ---------- 8. 开启 SSH 服务并生成 RSA 密钥 ----------
# 首次使用 SSH 需生成密钥对；执行后按提示输入密钥长度（如 2048）
stelnet server enable
rsa local-key-pair create

# ---------- 9. 配置 AAA 本地用户（示例用户 admin） ----------
# 密码请替换为实际强密码；irreversible-cipher 表示不可逆加密存储
aaa
local-user admin password irreversible-cipher YourPassword@123
local-user admin privilege level 15
local-user admin service-type ssh
quit

# 部分 VRP 版本还需显式指定 SSH 用户认证方式，如需要可取消注释：
ssh user admin authentication-type password
ssh user admin service-type stelnet

# ---------- 10. 配置 VTY 线路：AAA 认证，仅允许 SSH ----------
user-interface vty 0 4
authentication-mode aaa
protocol inbound ssh
quit

# ---------- 11. 保存配置（必须执行，否则重启丢失） ----------
# 退出到用户视图后执行 save，系统提示确认时输入 Y
quit
save

# ============================================================
# 配置后验证命令（在用户视图执行）：
# display clock                    查看时区、时间和日期
# display current-configuration    查看当前运行配置
# display ip interface brief       查看接口 IP 和状态
# display vlan                     查看 VLAN 及端口成员
# display users                    查看当前登录会话
# ============================================================
```

**使用提醒**：`rsa local-key-pair create` 和 `save` 是交互式命令，执行后需按提示输入密钥长度或确认 `Y`；其余命令可直接粘贴。若交换机已有配置，变更前建议先执行 `display current-configuration` 留存基线。

### 二层交换机和三层交换机的区别

#### 核心区别

**二层交换机基于 MAC 地址转发，工作在数据链路层，只会在同一个广播域内“送帧”；三层交换机基于 IP 地址转发，具备路由能力，工作在网络层，能在不同网段之间“路由+交换”。**

#### 对比总表

| 对比维度         | 二层交换机                                | 三层交换机                       |
| :----------- | :----------------------------------- | :-------------------------- |
| **工作层次**     | OSI 数据链路层（L2）                        | 网络层（L3），同时具备 L2 交换能力        |
| **转发依据**     | **目的 MAC 地址**                        | **目的 IP 地址**（同网段仍走 MAC 转发）  |
| **核心表项**     | MAC 地址表                              | MAC 地址表 + **路由表** + ARP 表   |
| **广播域**      | 一个端口一个冲突域，**整台交换机通常一个广播域**（除非划 VLAN） | 每个 VLAN 一个广播域，**VLAN 间可路由** |
| **VLAN 间通信** | **不能**，必须借助外部路由器或三层设备                | **可以**，通过 SVI/VLANIF 接口直接路由 |
| **是否支持路由协议** | 不支持                                  | 支持静态路由、OSPF、RIP、BGP 等（视型号）  |
| **转发性能**     | 高，纯硬件 ASIC 转发                        | 高，路由通常也由 ASIC/硬件加速，接近线速     |
| **成本**       | 较低                                   | 较高                          |
| **典型位置**     | 接入层                                  | 汇聚层/核心层                     |
| **典型用途**     | 终端接入、同网段互通                           | 跨网段互通、VLAN 间路由、汇聚接入         |

#### 补充：三层交换机与路由器的区别

三层交换机虽然能做路由，但和传统路由器仍有差异：

- **三层交换机**：路由功能通常由 **ASIC 硬件加速**，转发性能高、端口密度大、成本相对低，适合**局域网内部**的高速跨网段转发；但 NAT、VPN、复杂策略等广域网功能通常较弱。
- **路由器**：软件转发为主（高端也有硬件加速），接口类型丰富，支持 NAT、PPPoE、VPN、防火墙等广域网特性，适合**出口和跨广域网互联**。

所以常见架构是：**接入用二层交换机 → 汇聚/核心用三层交换机做内网路由 → 出口用路由器或防火墙连运营商**。

#### 选型建议

- **只需要同网段接入、VLAN 隔离**：二层交换机足够，成本低。
- **需要 VLAN 间互通、跨网段路由**：选三层交换机，避免“二层交换机 + 外部路由器”的单臂路由瓶颈。
- **大型网络**：接入层二层、汇聚/核心层三层是经典分层架构。
- **注意**：很多三层交换机也支持完整的二层功能，不是“三层就不能做二层”；选型时看**是否需要路由能力**和**预算**即可。
