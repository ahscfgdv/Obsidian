**路由（Route）就是数据从源到目的地过程中，经过一个个路口时被逐跳“指路”的过程**。而路由器就是那些站在路口、手里拿着地图、负责告诉数据“下一步往哪走”的设备。地图上记录的就是“去哪个网段该走哪条路”，这张地图就是**路由表**。

## 分类

### 路由协议的基本分类

网络层路由协议通常按作用范围分为两类：

- **IGP（Interior Gateway Protocol，内部网关协议）**：用于同一个自治系统（AS）内部，如 OSPF、IS-IS、RIP、EIGRP。
- **EGP（Exterior Gateway Protocol，外部网关协议）**：用于不同自治系统之间，当前事实标准是 **BGP**。

按算法还可分：

- **距离矢量**：RIP、EIGRP（高级距离矢量）
- **链路状态**：OSPF、IS-IS
- **路径矢量**：BGP

### 常见 IGP 路由协议

| 协议 | 类型 | 特点 | 常见场景 |
|---|---|---|---|
| **RIP/RIPng** | 距离矢量 | 以跳数为度量，最大 15 跳，配置简单，收敛慢 | 小型网络、实验环境、简单分支 |
| **OSPF/OSPFv3** | 链路状态 | 基于 SPF，收敛快，支持区域划分、VLAN/多区域 | 企业网、园区网、IDC 内部网络 |
| **IS-IS** | 链路状态 | 基于 SPF，扩展性好，常与 BGP 配合 | 运营商骨干、大型数据中心骨干 |
| **EIGRP** | 高级距离矢量 | 思科私有为主，收敛快，配置相对简单 | 思科设备为主的企业网 |

### 常见 EGP 路由协议

| 协议 | 类型 | 特点 | 常见场景 |
|---|---|---|---|
| **BGP/BGP4+** | 路径矢量 | 基于 AS 路径选路，策略丰富，可承载海量路由 | IDC 出口、多线接入、跨 AS 互联、云网互联 |

BGP 又分：

- **iBGP**：同一 AS 内部 BGP 邻居；
- **eBGP**：不同 AS 之间 BGP 邻居。

### IDC 运维中的常见选型

- **IDC 内部网络**：中小规模常用 **OSPF**；大型骨干或运营商环境常用 **IS-IS**。
- **IDC 出口/多线接入**：几乎必用 **BGP**，用于与运营商、云厂商或其他 AS 交换路由。
- **小型或简单网络**：可能用 **RIP** 或静态路由。
- **思科生态**：可能见到 **EIGRP**。
- **静态路由/默认路由**：不是动态路由协议，但运维中非常常见，常与动态协议配合使用。

### 运维关注点

- **OSPF**：关注邻居状态、区域划分、DR/BDR、LSA、路由汇总和收敛。
- **IS-IS**：关注 Level-1/Level-2、NET、邻居和链路度量。
- **BGP**：关注邻居状态、AS 路径、路由策略、前缀过滤、最大前缀数和路由震荡。
- **RIP**：关注跳数限制、收敛慢和环路风险。
- **EIGRP**：关注邻居、可行距离、报告距离和路由表一致性。


## 静态路由

### 定义与基本原理

**静态路由（Static Route）** 是由网络管理员**手动配置**的路由条目，明确指定“去往某个目的网段，下一跳交给哪个地址”或“从哪个接口发出”。它不依赖任何动态路由协议，路由器不会自动学习或更新，条目一旦写入就固定存在，除非管理员修改或删除。

静态路由的核心逻辑非常简单：**管理员告诉路由器“去某处该怎么走”，路由器照做即可。** 它不参与路由计算、不发送路由更新报文、不与邻居协商，因此没有协议开销，也没有收敛过程。

### 静态路由的组成要素

一条典型的静态路由通常包含以下要素：

- **目的网段/目的地址**：要到达的目标网络，如 `192.168.10.0/24`。
- **子网掩码/前缀长度**：与目的网段配合，确定匹配范围。
- **下一跳地址（Next Hop）**：数据包交给哪个相邻路由器的接口IP。
- **出接口（Outgoing Interface）**：从本机哪个接口发出，有时可与下一跳二选一或同时指定。
- **优先级/度量值（可选）**：用于多条静态路由共存时的选路，或与动态路由比较优先级。
- **管理距离（Administrative Distance，AD）**：不同来源路由的信任优先级，静态路由通常AD值很小（如思科默认1），优先级高于多数动态路由。

### 常见类型与特殊用法

静态路由不只是“一条普通路由”，在实际网络中有多种变体和特殊用法：

- **默认路由（Default Route）**：目的网段为 `0.0.0.0/0` 的静态路由，表示“所有没有明确匹配的路由都走这里”。常用于出口路由器指向ISP，或末端设备指向网关。
- **浮动静态路由（Floating Static Route）**：配置一条主静态路由和一条备份静态路由，备份路由的管理距离设得更大（优先级更低）。主路由失效时，备份路由才会被激活进入路由表，实现简单的冗余备份。
- **黑洞路由（Blackhole Route）**：将某目的网段指向 `Null0` 或丢弃接口，用于主动丢弃流量，常用于防环、封堵攻击源或汇总路由的防黑洞。
- **汇总静态路由**：将多条明细路由汇总为一条指向同一方向的静态路由，减少路由表规模。
- **主机路由**：目的地址为单个主机（如 `/32`），用于精确控制某台主机的走向。
- **带出接口的静态路由**：在点对点链路（如PPP、HDLC）上可直接指定出接口，不需要下一跳；在以太网等多路访问网络中，通常需要指定下一跳地址，否则可能引发ARP解析问题。

### 配置示例（以常见厂商为例）

**华为/H3C（VRP/Comware）** ：

```bash
# 基本静态路由：去往 192.168.10.0/24，下一跳 10.0.0.2
ip route-static 192.168.10.0 255.255.255.0 10.0.0.2

# 默认路由
ip route-static 0.0.0.0 0.0.0.0 10.0.0.1

# 浮动静态路由：备份路径，优先级设为 100（默认60，数值越大优先级越低）
ip route-static 192.168.10.0 255.255.255.0 10.0.0.3 preference 100

# 黑洞路由
ip route-static 192.168.20.0 255.255.255.0 NULL0
```

**思科（IOS）** ：

```bash
ip route 192.168.10.0 255.255.255.0 10.0.0.2
ip route 0.0.0.0 0.0.0.0 10.0.0.1
ip route 192.168.10.0 255.255.255.0 10.0.0.3 200   # 200为管理距离，实现浮动
ip route 192.168.20.0 255.255.255.0 Null0
```

**Linux**：

```bash
ip route add 192.168.10.0/24 via 10.0.0.2 dev eth0
ip route add default via 10.0.0.1
ip route add 192.168.20.0/24 blackhole
```

### 静态路由的优点

- **配置简单直观**：一条命令即可完成，无需理解复杂协议。
- **无协议开销**：不发送路由更新报文，不占用CPU和带宽，适合资源受限设备。
- **可控性强**：路径完全由管理员决定，不存在动态协议选路的不确定性。
- **安全**：不接收外部路由更新，不会被恶意路由注入影响（但需注意配置本身的安全性）。
- **稳定**：没有收敛过程，不会因协议震荡导致路由抖动。
- **适合简单拓扑**：末端网络、单出口、星型拓扑等场景下，静态路由足够且高效。

### 静态路由的缺点

- **无法自动适应拓扑变化**：链路或节点故障时，静态路由不会自动切换（除非配置了浮动静态路由），需要人工介入。
- **维护成本高**：网络规模增大时，逐台逐条配置和修改的工作量急剧上升，容易出错。
- **扩展性差**：不适合大型、动态变化的网络。
- **缺乏灵活性**：新增网段、调整路径都需要手动修改每台相关设备。
- **排障依赖人工**：没有协议邻居状态和路由更新日志，故障定位更依赖管理员对拓扑的熟悉程度。

### 典型应用场景

- **末端网络/ stub 网络**：只有一条出口路径的网络，用一条默认路由即可。
- **出口路由器指向ISP**：企业或IDC出口路由器通常配置默认路由指向运营商。
- **安全隔离与精确控制**：需要精确指定某段流量走向时，静态路由比动态协议更可控。
- **浮动备份**：作为动态路由或主静态路由的备份路径。
- **黑洞封堵**：将攻击流量或不需要的流量指向Null0丢弃。
- **小型网络或实验环境**：拓扑简单、设备少，静态路由足够。
- **与动态路由配合**：在OSPF/BGP网络中，用静态路由做默认路由下发或特定前缀的精确控制。

### 运维中的关注点与排障

在IDC运维中，静态路由虽然简单，但仍有几个常见坑点：

- **下一跳不可达**：静态路由本身不会感知下一跳是否可达，如果下一跳地址无法ARP解析或链路断开，路由条目可能仍在路由表中但流量被丢弃。需结合接口状态和ARP表排查。
- **递归路由问题**：下一跳地址本身需要通过另一条路由到达，若该路由缺失或变化，静态路由会失效。
- **浮动静态路由的主备切换**：需确认主路由失效后备份路由能否正确进入路由表，以及主路由恢复后能否正确切回。
- **管理距离/优先级冲突**：静态路由与动态路由共存时，需确认管理距离设置是否符合预期，避免静态路由意外覆盖动态路由或反之。
- **默认路由的副作用**：默认路由过于宽泛，可能掩盖明细路由缺失的问题，排障时需确认流量实际走向。
- **配置一致性**：多台设备上的静态路由需保持一致，变更时容易遗漏某台设备导致路径不对称。
- **文档与台账**：静态路由没有协议自动发现机制，必须靠文档和台账维护，建议记录每条静态路由的目的、下一跳、用途和变更记录。

### OSPF

#### 一句话定义

OSPF（Open Shortest Path First，开放式最短路径优先）是一种基于**链路状态（Link-State）** 算法的**内部网关协议（IGP）**，用于在企业或IDC的同一个自治系统（AS）内部，动态计算并维护无环路的最优路由路径。

#### 核心内涵

OSPF的核心内涵是 **“全网拼图，各自导航”**。与RIP这种“只告诉邻居我怎么走”的距离矢量协议不同，OSPF网络中每台路由器都会收集全网的链路状态信息（谁和谁连着、带宽多少），拼凑出一张完整的“全网地图”（LSDB，链路状态数据库），然后自己用数学算法算出到达每个目的地的最短路线。这就像司机不仅知道下一站怎么走，手里还拿着一张实时更新的全国高速公路地图。

#### 关键特征

- **无环路由**：基于SPF算法，从树根到树叶的计算方式天然避免了路由环路。
- **分级分域**：支持将网络划分为多个**区域（Area）**，通过骨干区域（Area 0）互联，有效限制了拓扑变化的影响范围和LSA泛洪。
- **触发更新与组播**：网络拓扑变化时迅速触发更新，并使用组播地址（如224.0.0.5/6）发送报文，减少对非相关设备的干扰。
- **以开销（Cost）为度量**：不以跳数为度量，而是根据接口带宽计算Cost值（通常为参考带宽÷接口带宽），带宽越大越优先。

#### 原理/机制

OSPF的运行可概括为“**找邻居—传地图—算路由**”三步：
1. **建立邻居**：路由器通过互相发送**Hello报文**发现并建立邻居关系（如2-Way、Full状态）。
2. **同步数据库**：邻居建立后，双方交换**LSA（链路状态通告）**，描述各自直连的网段和链路Cost。最终所有路由器的**LSDB**达到完全一致。
3. **运行SPF计算**：每台路由器以自己为根，运行SPF（Dijkstra）算法，计算出到达各网段的无环最短路径树（SPT），并将最优路径下发到路由表。

#### 分类或类型

- **版本分类**：**OSPFv2**（用于IPv4网络，IDC最常见）、**OSPFv3**（用于IPv6网络）。
- **区域类型**：**骨干区域（Area 0）**（所有其他区域必须直连或虚连接到它）、**普通区域**、以及为了减少LSA开销而设计的**特殊区域**（如Stub、Totally Stub、NSSA）。
- **网络类型**：广播多路访问（如以太网）、点对点（P2P）、非广播多路访问（NBMA）、点到多点（P2MP）。

#### 典型例子

在IDC机房的三层网络架构中，核心交换机与汇聚交换机之间通常运行OSPF。运维人员会将核心交换机配置为Area 0，各汇聚交换机配置为Area 1、Area 2等。通过手工修改核心与汇聚互联接口的**OSPF Cost值**，可以人为引导部分业务流量走联通专线，另一部分走电信专线。日常排障时，运维人员常敲击 `display ospf peer` 查看邻居状态是否Full，若卡在ExStart/Exchange状态，往往意味着接口MTU不匹配或两边存在单向链路。

### BFD

#### 一句话定义
BFD（Bidirectional Forwarding Detection，双向转发检测）是一种用于快速检测网络中两台相邻设备之间双向转发路径是否发生故障的通用、轻量级网络协议。

#### 核心内涵
BFD的本质是给网络链路装上一个 **“独立的高频心跳监测仪”**。在复杂网络中，路由协议（如OSPF、BGP）自带的检测机制通常比较慢（几十秒甚至几分钟）。BFD通过独立于上层协议的极速探测，一旦发现链路不通，立刻通知上层协议，从而实现网络的毫秒级快速收敛。它不负责计算路由，只负责“探路”。

#### 关键特征
- **毫秒级检测**：能将故障检测时间从秒级压缩到毫秒级（如50ms或100ms），极大减少业务中断时间。
- **协议无关性**：独立运行，不依赖具体的介质或上层协议，既可以服务于OSPF，也能服务于BGP、静态路由等。
- **轻量级低开销**：报文极小，格式极其精简，对设备CPU和链路带宽的消耗微乎其微。
- **双向检测**：能够在同一条链路的两个方向上同时进行故障探测。

#### 原理/机制
BFD的运行分为“协商、探测、通报”三步：
1. **会话建立（协商）**：两台设备的BFD通过三次握手建立会话，并在报文中协商好三个关键时间参数：发送间隔、接收间隔和**检测倍数**（本地检测时间 = 接收间隔 × 检测倍数）。
2. **高频探测**：建立后，双方以极短的间隔（如每100毫秒）互发轻量级的BFD控制报文。
3. **超时判定与联动**：如果在本地检测时间内没收到对端报文，系统立刻判定链路故障（Down），并立即通知绑定它的上层协议（如OSPF进程）。OSPF收到通知后，无需再苦等自身的40秒超时，而是瞬间拆除邻居关系并切换备用路由。

#### 分类或类型
- **按工作模式**：**异步模式**（最常用，双方周期性互发报文）和**查询模式**（只在需要时发送，节省资源）。
- **按应用场景**：**单跳BFD**（用于直连设备，常见于IDC内网链路）、**多跳BFD**（用于跨越多台设备的非直连检测）、**Echo BFD**（利用本地路由表将探测包发回自己，减轻对端设备CPU负担）。

#### 典型例子
在IDC核心与汇聚交换机的互联架构中，运维人员通常会同时配置OSPF和BFD。假设一根光纤被施工意外挖断，如果没有BFD，OSPF需要等待40秒的Dead定时器超时才会切换路径，业务会卡顿甚至掉线；而启用BFD后，BFD在300毫秒内就发现报文中断，立刻通知OSPF断开邻居，OSPF瞬间将流量切换到备用链路上，业务几乎无感知。这就是BFD在IDC高可用网络中不可替代的价值。

## 度量

#### 一句话定义

路由的度量（Route Metric）是路由器在计算通往同一目标网络的多条路径时，用来评估每条路径“优劣”的量化标准或数值（通常称为“开销”或“代价”），路由器总是优先选择度量值最小的路径来转发数据。

#### 核心内涵

路由度量的本质是网络设备的**路径选择评分系统**。在复杂的网络中，到达同一个目的IP往往有多条路径，路由器需要一把“尺子”来衡量哪条路更好。这把尺子就是度量值。可以把它类比为用导航软件规划行程：从A地到B地，有高速（快但收费）、国道（免费但慢）和乡道（距离近但难走），导航软件通过综合计算时间、距离和路费（即“度量”），为你推荐最优路线。需要区分的是：**管理距离（AD）** 用于在**不同路由协议**（如OSPF与BGP）之间选优（信谁）；而**度量（Metric）** 是在**同一种路由协议**内部，在多条路径之间选优（走哪）。

#### 关键特征

- **同协议内比较**：度量值只在同一种路由协议内部有意义。OSPF的度量值“10”与RIP的度量值“10”毫无可比性。
- **数值越小越优**：绝大多数路由协议（如OSPF、RIP）都遵循“度量值越小，路径越优”的原则（BGP除外，它是选最长的特定路径属性）。
- **动态累加与更新**：度量值往往随着路由通告在网络上传播并累加（如跳数），当链路带宽变化或发生故障时，度量值会重新计算。
- **可人为干预**：在IDC运维中，管理员经常通过修改度量值（如调整接口Cost值）来人为引导流量走向，实现流量工程。

#### 原理/机制

以最常见的**链路状态协议（OSPF）** 为例：每台路由器都会计算自己每个接口的**开销（Cost）**，计算公式通常为 `参考带宽 ÷ 接口带宽`（带宽越高，Cost越小）。当路由器向外泛洪路由信息时，会带上该路径的累加Cost。路由器收集到全网信息后，运行SPF（最短路径优先）算法，计算到达每个目标网段的总Cost，并将总Cost最小的路径放入路由表。如果主路径断开，次优（Cost稍大）的路径会立刻顶上。

#### 分类或类型

不同路由协议选用的度量标准（尺子）完全不同：

- **跳数（Hop Count）**：**RIP协议**的度量。每经过一台路由器算1跳。最大15跳，16跳视为不可达。简单粗暴，不考虑带宽。
- **带宽/开销（Cost）**：**OSPF和IS-IS协议**的度量。基于接口物理带宽计算，带宽越大，开销越小（Metric越小），完美契合现代高速网络。
- **复合度量（Composite Metric）**：**EIGRP协议**的度量。综合考量**带宽（Bandwidth）** 和**延迟（Delay）** （默认情况下），甚至可加入负载和可靠性，能更全面地反映链路质量。
- **路径属性（Path Attributes）**：**BGP协议**的度量。BGP在互联网边界使用，不采用简单的带宽或跳数，而是通过 `AS-Path`（经过的自治系统数量）、`Local Preference`（本地优先级）等复杂的策略属性来选路。

#### 典型例子

假设一个IDC内网运行OSPF，核心交换机C1和C2都连接着目标服务器网段。接入交换机A有两条上行链路：到C1的万兆链路（Cost = 1），到C2的千兆链路（Cost = 10）。根据OSPF的度量机制，A计算得出经C1去往目标网段的总开销为1，经C2为10。因此，A会将C1设为最优下一跳，所有业务流量默认走万兆链路；只有当万兆链路故障时，路由表才会自动收敛，将千兆链路（次优度量）顶替上来，确保网络的高可用与带宽利用最大化。
