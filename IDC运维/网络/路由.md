**路由（Route）就是数据从源到目的地过程中，经过一个个路口时被逐跳“指路”的过程**。而路由器就是那些站在路口、手里拿着地图、负责告诉数据“下一步往哪走”的设备。地图上记录的就是“去哪个网段该走哪条路”，这张地图就是**路由表**。

## 分类

### 路由协议的基本分类

网络层路由协议通常按作用范围分为两类：

- **IGP（Interior Gateway Protocol，内部网关协议）**：用于同一个自治系统（AS）内部，如 OSPF、IS-IS、RIP、EIGRP。
- **EGP（Exterior Gateway Protocol，外部网关协议）**：用于不同自治系统之间，当前事实标准是 **BGP**。

按算法还可分：

- **距离矢量**：RIP、EIGRP（高级距离矢量）
- **链路状态**：OSPF、IS-IS
- **路径矢量**：BGP

### 常见 IGP 路由协议

| 协议 | 类型 | 特点 | 常见场景 |
|---|---|---|---|
| **RIP/RIPng** | 距离矢量 | 以跳数为度量，最大 15 跳，配置简单，收敛慢 | 小型网络、实验环境、简单分支 |
| **OSPF/OSPFv3** | 链路状态 | 基于 SPF，收敛快，支持区域划分、VLAN/多区域 | 企业网、园区网、IDC 内部网络 |
| **IS-IS** | 链路状态 | 基于 SPF，扩展性好，常与 BGP 配合 | 运营商骨干、大型数据中心骨干 |
| **EIGRP** | 高级距离矢量 | 思科私有为主，收敛快，配置相对简单 | 思科设备为主的企业网 |

### 常见 EGP 路由协议

| 协议 | 类型 | 特点 | 常见场景 |
|---|---|---|---|
| **BGP/BGP4+** | 路径矢量 | 基于 AS 路径选路，策略丰富，可承载海量路由 | IDC 出口、多线接入、跨 AS 互联、云网互联 |

BGP 又分：

- **iBGP**：同一 AS 内部 BGP 邻居；
- **eBGP**：不同 AS 之间 BGP 邻居。

### IDC 运维中的常见选型

- **IDC 内部网络**：中小规模常用 **OSPF**；大型骨干或运营商环境常用 **IS-IS**。
- **IDC 出口/多线接入**：几乎必用 **BGP**，用于与运营商、云厂商或其他 AS 交换路由。
- **小型或简单网络**：可能用 **RIP** 或静态路由。
- **思科生态**：可能见到 **EIGRP**。
- **静态路由/默认路由**：不是动态路由协议，但运维中非常常见，常与动态协议配合使用。

### 运维关注点

- **OSPF**：关注邻居状态、区域划分、DR/BDR、LSA、路由汇总和收敛。
- **IS-IS**：关注 Level-1/Level-2、NET、邻居和链路度量。
- **BGP**：关注邻居状态、AS 路径、路由策略、前缀过滤、最大前缀数和路由震荡。
- **RIP**：关注跳数限制、收敛慢和环路风险。
- **EIGRP**：关注邻居、可行距离、报告距离和路由表一致性。


## 静态路由

### 定义与基本原理

**静态路由（Static Route）** 是由网络管理员**手动配置**的路由条目，明确指定“去往某个目的网段，下一跳交给哪个地址”或“从哪个接口发出”。它不依赖任何动态路由协议，路由器不会自动学习或更新，条目一旦写入就固定存在，除非管理员修改或删除。

静态路由的核心逻辑非常简单：**管理员告诉路由器“去某处该怎么走”，路由器照做即可。** 它不参与路由计算、不发送路由更新报文、不与邻居协商，因此没有协议开销，也没有收敛过程。

### 静态路由的组成要素

一条典型的静态路由通常包含以下要素：

- **目的网段/目的地址**：要到达的目标网络，如 `192.168.10.0/24`。
- **子网掩码/前缀长度**：与目的网段配合，确定匹配范围。
- **下一跳地址（Next Hop）**：数据包交给哪个相邻路由器的接口IP。
- **出接口（Outgoing Interface）**：从本机哪个接口发出，有时可与下一跳二选一或同时指定。
- **优先级/度量值（可选）**：用于多条静态路由共存时的选路，或与动态路由比较优先级。
- **管理距离（Administrative Distance，AD）**：不同来源路由的信任优先级，静态路由通常AD值很小（如思科默认1），优先级高于多数动态路由。

### 常见类型与特殊用法

静态路由不只是“一条普通路由”，在实际网络中有多种变体和特殊用法：

- **默认路由（Default Route）**：目的网段为 `0.0.0.0/0` 的静态路由，表示“所有没有明确匹配的路由都走这里”。常用于出口路由器指向ISP，或末端设备指向网关。
- **浮动静态路由（Floating Static Route）**：配置一条主静态路由和一条备份静态路由，备份路由的管理距离设得更大（优先级更低）。主路由失效时，备份路由才会被激活进入路由表，实现简单的冗余备份。
- **黑洞路由（Blackhole Route）**：将某目的网段指向 `Null0` 或丢弃接口，用于主动丢弃流量，常用于防环、封堵攻击源或汇总路由的防黑洞。
- **汇总静态路由**：将多条明细路由汇总为一条指向同一方向的静态路由，减少路由表规模。
- **主机路由**：目的地址为单个主机（如 `/32`），用于精确控制某台主机的走向。
- **带出接口的静态路由**：在点对点链路（如PPP、HDLC）上可直接指定出接口，不需要下一跳；在以太网等多路访问网络中，通常需要指定下一跳地址，否则可能引发ARP解析问题。

### 配置示例（以常见厂商为例）

**华为/H3C（VRP/Comware）** ：

```bash
# 基本静态路由：去往 192.168.10.0/24，下一跳 10.0.0.2
ip route-static 192.168.10.0 255.255.255.0 10.0.0.2

# 默认路由
ip route-static 0.0.0.0 0.0.0.0 10.0.0.1

# 浮动静态路由：备份路径，优先级设为 100（默认60，数值越大优先级越低）
ip route-static 192.168.10.0 255.255.255.0 10.0.0.3 preference 100

# 黑洞路由
ip route-static 192.168.20.0 255.255.255.0 NULL0
```

**思科（IOS）** ：

```bash
ip route 192.168.10.0 255.255.255.0 10.0.0.2
ip route 0.0.0.0 0.0.0.0 10.0.0.1
ip route 192.168.10.0 255.255.255.0 10.0.0.3 200   # 200为管理距离，实现浮动
ip route 192.168.20.0 255.255.255.0 Null0
```

**Linux**：

```bash
ip route add 192.168.10.0/24 via 10.0.0.2 dev eth0
ip route add default via 10.0.0.1
ip route add 192.168.20.0/24 blackhole
```

### 静态路由的优点

- **配置简单直观**：一条命令即可完成，无需理解复杂协议。
- **无协议开销**：不发送路由更新报文，不占用CPU和带宽，适合资源受限设备。
- **可控性强**：路径完全由管理员决定，不存在动态协议选路的不确定性。
- **安全**：不接收外部路由更新，不会被恶意路由注入影响（但需注意配置本身的安全性）。
- **稳定**：没有收敛过程，不会因协议震荡导致路由抖动。
- **适合简单拓扑**：末端网络、单出口、星型拓扑等场景下，静态路由足够且高效。

### 静态路由的缺点

- **无法自动适应拓扑变化**：链路或节点故障时，静态路由不会自动切换（除非配置了浮动静态路由），需要人工介入。
- **维护成本高**：网络规模增大时，逐台逐条配置和修改的工作量急剧上升，容易出错。
- **扩展性差**：不适合大型、动态变化的网络。
- **缺乏灵活性**：新增网段、调整路径都需要手动修改每台相关设备。
- **排障依赖人工**：没有协议邻居状态和路由更新日志，故障定位更依赖管理员对拓扑的熟悉程度。

### 典型应用场景

- **末端网络/ stub 网络**：只有一条出口路径的网络，用一条默认路由即可。
- **出口路由器指向ISP**：企业或IDC出口路由器通常配置默认路由指向运营商。
- **安全隔离与精确控制**：需要精确指定某段流量走向时，静态路由比动态协议更可控。
- **浮动备份**：作为动态路由或主静态路由的备份路径。
- **黑洞封堵**：将攻击流量或不需要的流量指向Null0丢弃。
- **小型网络或实验环境**：拓扑简单、设备少，静态路由足够。
- **与动态路由配合**：在OSPF/BGP网络中，用静态路由做默认路由下发或特定前缀的精确控制。

### 运维中的关注点与排障

在IDC运维中，静态路由虽然简单，但仍有几个常见坑点：

- **下一跳不可达**：静态路由本身不会感知下一跳是否可达，如果下一跳地址无法ARP解析或链路断开，路由条目可能仍在路由表中但流量被丢弃。需结合接口状态和ARP表排查。
- **递归路由问题**：下一跳地址本身需要通过另一条路由到达，若该路由缺失或变化，静态路由会失效。
- **浮动静态路由的主备切换**：需确认主路由失效后备份路由能否正确进入路由表，以及主路由恢复后能否正确切回。
- **管理距离/优先级冲突**：静态路由与动态路由共存时，需确认管理距离设置是否符合预期，避免静态路由意外覆盖动态路由或反之。
- **默认路由的副作用**：默认路由过于宽泛，可能掩盖明细路由缺失的问题，排障时需确认流量实际走向。
- **配置一致性**：多台设备上的静态路由需保持一致，变更时容易遗漏某台设备导致路径不对称。
- **文档与台账**：静态路由没有协议自动发现机制，必须靠文档和台账维护，建议记录每条静态路由的目的、下一跳、用途和变更记录。
