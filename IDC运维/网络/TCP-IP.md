## TCP/IP模型


### ARP

#### 定义与定位：连接网络层与链路层的桥梁

**ARP（Address Resolution Protocol，地址解析协议）** 的核心任务，是在**IPv4**网络中，将已知的**逻辑地址（IP地址）** 解析为**物理地址（MAC地址）**。

网络通信存在一个根本矛盾：上层**网络层**使用IP地址进行寻址和路由，而底层**数据链路层**（如以太网）在实际传输数据帧时，只“认识”MAC地址。设备无法直接将IP数据报交给目标主机，必须先知道对方的MAC地址才能封装成帧发送出去。ARP就是为了填补这个**协议地址与硬件地址之间的鸿沟**而设计的。

ARP工作在**网络层与数据链路层之间**，其报文不封装在IP包内，而是直接作为以太网帧的数据载荷进行传输。

#### 核心机制：缓存优先，广播请求，单播应答

ARP的解析过程高效且直接，核心依赖于**ARP缓存表**和两种通信方式的配合。

1. **先查缓存**：任何设备发送数据前，首先检索本地的**ARP缓存表**（也称ARP映射表），查找目标IP是否已有对应的MAC地址记录。
2. **缓存未命中 → 广播请求**：若表中没有记录，发送方会构造一个**ARP请求**，以**广播**形式（目的MAC为 `FF:FF:FF:FF:FF:FF`）发往局域网内所有设备。请求中携带了“我想找的IP地址”以及自己的IP和MAC。**
3. **目标应答 → 单播回复**：局域网内所有设备都会收到广播，但**只有IP地址与请求匹配的那台设备**会进行响应。它以**单播**方式直接回复一个**ARP应答**，告诉请求方自己的MAC地址。
4. **更新缓存**：请求方收到应答后，将这对IP-MAC映射关系写入自己的ARP缓存表，随后即可用该MAC地址封装并发送数据。同时，应答方也会从请求中学习到请求方的映射并缓存。

ARP缓存表项通常有**老化时间**（如几分钟到几十分钟），过期后会被清除，以确保能适应网络中IP-MAC映射关系的变化。

#### 报文格式与关键标识

ARP报文格式固定，长度为**28字节**（不含以太网帧头）。其在以太网帧中的关键标识是**帧类型（EtherType）字段为 `0x0806`**，表明载荷是ARP报文。ARP报文本身的关键字段如下：

| 字段 | 典型值 (IPv4/以太网) | 作用 |
| :--- | :--- | :--- |
| **硬件类型** | `1` | 表示以太网 |
| **协议类型** | `0x0800` | 表示要解析的是IPv4地址 |
| **操作码 (Opcode)** | `1`=请求，`2`=应答 | **区分报文类型的关键** |
| **发送方 MAC/IP** | 本机真实地址 | 用于对方学习并建立缓存 |
| **目标 MAC** | 请求中为**全0** | 请求时未知，应答时填入目标MAC |
| **目标 IP** | 待解析的IP | 要查询的目标地址 |

> **注意**：ARP请求的“目标MAC”字段为全0，是因为请求方正是在询问这个值；而“以太网目的地址”为广播地址，是二层帧头的属性，与ARP载荷内的“目标MAC”字段不同。

#### 补充与衍生：不止于IPv4

*   **RARP（反向ARP）**：功能与ARP相反，用于让设备通过自己的MAC地址来请求获取IP地址，早期用于无盘工作站。现已被DHCP取代。
*   **免费ARP（Gratuitous ARP）**：设备主动发送ARP请求来查询**自己的IP地址**。主要用途有两个：一是**检测IP地址冲突**（如果有其他设备应答，则说明IP已被占用）；二是在设备MAC地址变更或主备切换时，**通知并刷新网络中其他设备的ARP缓存**。
*   **IPv6中的替代者**：在IPv6环境中，ARP的功能由**NDP（邻居发现协议）** 中的**NS/NA（邻居请求/通告）** 报文承担，并集成了路由器发现、地址自动配置等更多功能。

#### 核心安全风险：ARP欺骗与防御

ARP协议诞生于信任的网络环境，其设计**没有任何认证机制**，任何设备都可以声称某个IP地址对应自己的MAC。这一缺陷导致了局域网中最常见的攻击之一：**ARP欺骗（ARP Spoofing / Poisoning）**。

攻击者通过持续发送伪造的ARP应答，篡改目标设备ARP缓存中的IP-MAC映射关系，主要形式包括：
*   **仿冒网关**：攻击者冒充网关，使受害主机的流量发往攻击者，造成**断网**或**中间人攻击（MITM）**。
*   **仿冒用户**：攻击者冒充某台合法主机，欺骗网关或其他用户，导致数据被错误投递或窃听。
*   **泛洪攻击**：发送大量伪造ARP报文，耗尽交换机或主机的ARP表资源，导致正常通信无法建立。

**防御ARP欺骗需要网络设备侧的配合**，常见手段包括：
*   **静态ARP绑定**：在关键主机或网关上手动配置IP-MAC映射，优先级高于动态学习，但维护成本高。
*   **交换机侧防护**：在接入交换机上部署**ARP Detection**（检查ARP报文合法性）、**ARP过滤保护**（限制接口允许的IP-MAC对）或**DAI（动态ARP检测）** 等功能。
*   **专用安全设备**：部分防火墙或安全网关具备ARP欺骗防御能力。

#### IDC运维视角的关注点

在IDC运维中，ARP是网络排查的基础环节之一：
*   **连通性排查**：同网段设备“ping不通”时，检查双方ARP缓存中是否存在正确的映射条目是关键步骤。在Linux上可用 `ip neigh` 或 `arp -n`，在Windows上可用 `arp -a` 查看。
*   **ARP表容量与泛洪**：核心交换机或路由器的ARP表项数量是容量规划的一部分。异常的ARP表增长可能意味着存在扫描或泛洪攻击。
*   **网关ARP稳定性**：网关的ARP映射若被欺骗篡改，会导致大面积业务中断。在关键网络中，网关侧常采用静态绑定或接入层防护来保障稳定性。
*   **虚拟机环境**：在虚拟化或云环境中，ARP欺骗可能发生在虚拟机之间，需要依赖虚拟交换机或SDN控制器层面的ARP防护策略。

**总结来说，ARP是IPv4局域网赖以运转的“地址翻译官”，它用最简单的“广播问、单播答”机制解决了IP到MAC的映射问题，但也因缺乏认证而成为局域网安全的薄弱环节。**
