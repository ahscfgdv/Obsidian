## 第 0 章 记忆总纲

### 三句话记住整份笔记

1. **运维目标三保**：保在线（业务不中断）、保安全（人/设备/数据不出事）、保闭环（每件事有记录有结论）。
2. **一切操作的主线**：见单操作 → 核实四项信息 → 双人复核 → 操作 → 测试 → 结单归档。
3. **排障的通用思路**：分层定位（物理层→网络→系统→应用）+ 最小化/交叉测试 + BMC SEL 日志 + 闭环记录。

### 高频数字速记表（必背）

| 数字 | 含义 |
| :-- | :-- |
| **1-2-5-10** | 应急响应原则：1 分钟响应、2 分钟通报经理、5 分钟同步信息（联系不上升级总监）、10 分钟通告进度 |
| **4 项信息** | 操作前核实：机房包间号、机柜前（后）门编号、SN 号、U 位 |
| **6 要素** | 交换机整替核实：机房、机架、机位、固资、SN、机型 |
| **七步排查法** | ip link → ethtool → ip addr → ip route → ip neigh → ping 网关 → ping 外网 |
| **物数网传会表应** | OSI 七层口诀（从下到上） |
| **1U = 44.45mm** | 标准机架单位；42U 机柜理论装 21 台 2U，实际 12~14 台 |
| **100 米** | 双绞线（TIA/EIA-568）最大距离 = 90m 永久链路 + 两端各 5m 跳线 |
| **99.995%** | Tier IV（A 级）年可用性，全年停机 ≤26 分钟 |
| **12 通道** | AMD EPYC 9004/9005 内存通道；Intel Xeon 4/5 代为 8 通道 |
| **72bit = 64+8** | ECC 内存：64 位数据 + 8 位校验 |
| **9600 8N1** | Console 口默认参数：9600bps、8 数据位、1 停止位、无校验、无流控 |
| **8×8×8=512** | RAID 5 大盘（4TB+）不建议：重建读海量数据易遇 URE 导致二次故障 |

## 第 1 章 运维职责与作业规范

### 1.1 IDC 运维一句话总览

==通过"巡检 + 操作 + 故障处理 + 应急 + 随工"，保障机房 IT 资产及运行环境（供电、制冷、动环）持续、稳定、安全运行。==

**六大工作模块**（面试按此框架答）：

| 序号 | 模块 | 一句话 |
| :-- | :-- | :-- |
| 1 | 机房日常巡检 | 看环境、看设备，发现异常第一时间上报 |
| 2 | 设备上下架与资产盘点 | 到货验收、上架理线、下架搬迁、账实核对 |
| 3 | 服务器故障处理 | 定位更换硬件故障件，跟进厂商维修至恢复 |
| 4 | 网络故障处理 | 网线导通、联通检查与更换，处理硬件层故障 |
| 5 | 故障跟踪、上报与闭环 | 全程跟踪、及时通报、逐条结单 |
| 6 | 施工随工与应急处理 | 监督施工规范，突发掉电/温升/漏水时应急响应 |

> 运维工程师负责**硬件层面**（线缆、端口、联通性），**不涉及业务配置下发与变更**。

### 1.2 日常巡检

- **巡检对象**：环境侧（温湿度、动环、UPS、精密空调、消防漏水）、设备侧（服务器指示灯/BMC 告警、网络设备端口灯）、机柜侧（单路掉电、PDU、理线标签）。
- **正常温度**：冷通道一般 18~25℃（ASHRAE 标准 18~27℃，相对湿度 20%~80%）。
- **异常上报核心**：==巡检的核心不是"看到了什么"，而是"发现异常后怎么处理"==。掉电/环境异常第一时间反馈上报；无法恢复立即通知上级领导协调；未知设备/现象不擅自发散操作（可向同公司在岗人员咨询）。
- **小技巧**：封闭运行设备不便打开组件时，可通过**靠近听声音**辅助判断风扇、硬盘状态。

### 1.3 综合布线要求（理解性记忆）

- 横平竖直、整齐划一；强电弱电分离、光纤铜缆分离；光纤用魔术扎带绑扎。
- 余长收敛在机柜内，走线桥架严禁多余线缆。
- 标签正确标识起止位置，距端口 **5cm** 处整齐粘贴。
- 机柜进线预留足够长度，一般大于机柜宽度 **10cm**。
- 弯曲半径：非屏蔽双绞线 ≥线缆外径 **4 倍**；机柜顶部盘绕光缆/光纤余长 ≥外径 **10 倍**。

### 1.4 见单操作与信息核对

- **见单操作**：无工单（含飞书、邮件通知）的操作需书面文字发送 IT 运维组确认后再执行。
- **四项基本信息**（必背）：机房包间号、机柜前（后）门编号、SN 号、U 位——与工单完全一致。
- **双人复核**：关键操作双人复核；单人操作需发单人确认；**禁止一切账号相关操作**（改密码、建账号等）。
- 在线操作（硬盘在线更换、电源更换、AOC 网线更换）非业务确认禁止关机或重启。
- 所有关机、重启、插拔线缆**必须由现场运维执行**，严禁厂商操作。

## 第 2 章 安全红线与应急处理

### 2.1 安全红线（背原文要点）

**存储介质与接入**
- 禁止未经授权将 U 盘、移动硬盘等存储介质插入服务器 USB 接口。
- 禁止未经授权私自将笔记本接入服务器，或用网线/光纤直连设备（服务器↔服务器、交换机↔交换机）。
- 禁止以任何方式登录硬盘操作系统、内存操作系统进行命令或查看操作。
- 禁止任何人未经授权将存储介质、终端设备带入**红区**。

**信息保密（泄密范围 7 项）**：机房物理地址/数量/分布/联系人/运营商/图纸；机柜/PDU/头柜品牌型号数量；空调/配电/UPS/油机配置与故障；网络架构/业务架构/带宽/IP；设备品牌型号配置故障率/SLA；工单与邮件内容；标准规范/服务协议/SLA。

**机房行为**
- 严禁饮食饮水、吸烟、未经授权拍照录像；严禁携带背包包裹进入机房。
- 临时设备加电只能用**市电（墙电）**，禁止用机柜 PDU。
- 施工区域与生产区域用隔离带、警示牌隔离；严禁触碰工单外设备线缆。
- 禁止运维岗脱岗；办公电脑设密码锁屏，离岗锁屏；入离职转岗及时变更权限。

**外来人员**：非数据运营人员进包间需全程陪同；进出由 IT 工程师授权核对、登记、佩戴身份识别卡。

**厂商维修随工**：出示工单二维码扫码确认、全程陪同；线缆插拔/开关机由 IT 运维操作；禁止与工作无关行为。

### 2.2 应急"一二十五"原则

> 1 分钟响应告警并通知现场值班；2 分钟通报故障内容至现场运维经理；5 分钟同步进一步信息（联系不上经理升级至 IT 运维总监）；10 分钟通告处理进度直到完成。

### 2.3 五类应急场景处置（必背）

| 场景 | 关键动作（按序） |
| :-- | :-- |
| **机柜单路掉电** | 1 分钟上报+赶赴现场 → 确认掉电范围与宕机情况 → 设施排查列头柜空开到 PDU 接线：①有问题→掉电侧电源线全接临时 PDU，修好再接回；②无问题→拔除掉电侧设备电源线隔离后试送电，成功且未跳闸则逐台插回，找出故障电源模块并隔离 → 记录故障电源信息反馈客户 |
| **机房局部温升** | 1 分钟通知设施+赶赴现场 → 测温枪测冷通道温度，超 26℃ 协助降温（调低空调、开备用精密空调、设鼓风机）→ 查盲板/热通道门/服务器风扇 → 点温枪测服务器进风口 → 两小时内持续跟进巡检 |
| **机房漏水** | 1 分钟响应赶赴 → 2 分钟确认是否影响机柜设备并反馈 → 5 分钟反馈可控性与应急措施 → 10 分钟协助隔离排水 → 有设备宕机经设施+客户确认后在 **PDU 端**做电源隔离（**禁止设备端操作，防触电**）→ 检查相邻机柜必要时隔离电源 |
| **批量设备宕机恢复** | 按楼分组、2 人一组双重复核四项信息 → 粘贴操作标签 → 一人核对标签、一人核对 IP/SN 开机 → 楼长 10 分钟内统计进度上报 |
| **误操作处理** | 安全情况下停止一切操作 → 立即如实上报主管 → 详细记录事件经过与位置/SN/IP 等关键信息，**不隐瞒、不造假** |

### 2.4 对/错判断（面试陷阱高频）

**对**
- 未知设备/现象/故障，出于信息安全可向同公司在岗人员咨询，不擅自发散操作。
- 封闭运行设备可通过靠近听声音判断风扇/硬盘状态。
- 维修时（含厂商/自维修）进入包间**只允许带入本包间需维修的存储介质**。
- 减配工单发现服务器内无实物 → 失败结单；安全箱无法入箱 → 借用库房空安全箱。
- 维修工单是内存故障但实际故障件是 AEP → 转为 AEP 故障后再维修。
- JBOD 带外网卡：状态灯**常亮**表示带外口与上联交换机正常连接。
- MOC 有 OS 要进无盘：只能用串口线连 UART 口，按快捷键进无盘。

**错**
- 掉电机柜空开跳闸，为尽快恢复直接合闸（错，须排查）。
- 电源线上原机房标签两端一致就不更换（错，须换正确标签）；未带标签纸承诺次日贴（错）。
- 厂商未完成检测先行离开（错）；故障件存办公室/智能柜（错，须及时交资产岗入库）。
- A/B 路同时下电（错）；结单提示重启就直接重启（错，须确认）。
- 备件放已拆封防静电袋就使用（错）；雷神机型电源保护盖在不断电情况下安装（错）。
- 请物流人员帮忙插线（错）；一次申请两年门禁卡权限（错）；无明确备注默认直接操作（对）。
- 单人独立核对操作服务器重启工单（错，入职 1.5 年也不例外，关键操作须双人复核）。

## 第 3 章 SOP 标准作业流程

### 3.1 硬件更换通用主线（面试按此讲不会乱）

==**取件 → 双人复核 → 下架/断电 → 拆 → 装 → 测试 → 结单归库**==

- **取件**：接单领备件，核对 PN 与工单一致，观察外观有无损坏。
- **双人复核**：到达指定位置双人复核四项信息，粘贴防误操作标识牌与亚克力挡板。
- **下架/断电**：佩戴静电手环，按要求关机下架或断电。
- **拆**：核对拆下的故障件 SN 与工单一致；**拆除前拍照留痕**（防无法还原）。
- **装**：防呆标识对齐、硅脂涂抹规范。
- **测试**：开机后通过 BMC/BIOS 查看硬件状态，确认后结单。
- **结单归库**：记录新旧件 SN，故障件归还资产库。

**六要素/总结备注**：所有备件出库前核对 PN；故障件拆下后核对 SN，再核对新旧件 PN 一致；更换后**清除 BMC SEL 日志**并在 BMC/BIOS 查看硬件状态；结单记录新旧件 SN，故障件归库。

### 3.2 最小化测试（理解性记忆）

- **目的**：定位导致无法开机、开机自检卡死的故障硬件。
- **做法**：保留 1 个 CPU（CPU0）、1 根内存（插 CPU0 归属插槽）、1 个电源开机；能开机后**关机→逐件加回→开机**，逐步锁定故障硬件。
- **故障处理三步**：查电源 → 查 BMC → 最小化测试。

### 3.3 服务器上架流程

1. 按工单核对准备：U 位、PDU/电源线型号、接口与线缆数量、支架。
2. 到货开箱检查（磕碰异常、USB 有无外接存储）；上架前用**墙电（市电）开机测试**（防异常电源模块导致 PDU 短路掉电）。
3. 资产验收 → 指导搬运至机架位上架；全程监督防暴力操作、防触碰在线设备及 PDU。
4. 厂商工程师插电插线，**机房人员开机**（无法开机通知装机负责人）。

### 3.4 服务器下架流程

按单操作（工程师关机后方可操作）→ 核实四项信息后拔电源线和网线，机器前推 10cm 理线 → 拔电源线后检查在线设备有无掉电 → 物流上门指导搬运到交接区（轻拿轻放）→ 搬迁单签字、办出门手续。

### 3.5 服务器重启流程

双人复核四项信息、贴防误操作标识 → 长按电源键关机 → 拔电源线、长按电源 30 秒以上放电 → 插紧电源线、短按开机 → 进入 login 界面或无盘即成功。

### 3.6 各部件更换要点

| 部件 | 关键要点 |
| :-- | :-- |
| **CPU** | 对角松螺丝拆散热器，勿将硅脂沾到针脚；旧 CPU 背部硅脂清理干净放防静电袋；新 CPU 防呆对齐、背部均匀涂薄层硅脂；散热器对角拧紧；BMC/BIOS 验证 |
| **主板** | 核对 PN/CPU 针脚无弯曲；拆除前拍照留痕，对角松散热器；旧板硬件逐一有序装到新板；**刷写 FRU** 后上架开机 |
| **硬盘** | 备件 PN 一致；双人复核故障盘槽位；核对故障盘 SN 与工单、新旧盘 PN 一致；更换后 BMC/BIOS 验证，不正常按**硬盘背板→背板连接线→RAID 卡→主板**顺序排查 |
| **内存（不识别）** | 与正常内存交叉测试：报错位置转移→该内存故障；位置不变→交叉 CPU：转移→该内存控制 CPU 故障；仍不变→主板故障（BMC/BIOS 确认） |
| **电源** | 备件先**墙电测试**（指示灯绿色）；双人复核故障槽位、确认其他电源正常供电；佩戴静电手环更换；观察正常供电后结单 |
| **交换机扩容** | 备件板卡（含光模块）出库核对 PN/SN、外观；确认槽位可用、与派单人确认时间；贴标识、确认可操作后拆空白盖板插板卡固定；按标签端口号插光纤；确认端口正常后结单、空白盖板归库 |
| **交换机整机替换** | 出库核实型号/固资/SN，OS 版本与补丁一致否则先更新；刷配置文件（console + crt，`display cu` 查看、`save` 保存），`compare` 对比配置；核实 6 要素；下电前与派单人确认；平移电源/风扇/板卡/模块；上电接管理网线确认网管与配置；确认后接上下联链路；结单、故障机归资产 |

### 3.7 内存导致无法开机的排查流程

看指示（蜂鸣码/DEBUG 灯/SEL 日志）→ 断电安全（按电源键放电、戴静电手环）→ 最小化测试 → 单根逐一验证（区分坏条与坏槽）→ 交叉测试（条跟着走是坏条，槽跟着走是坏槽）→ 清洁复装（橡皮擦金手指，按插槽优先级先插远离 CPU 的第一槽如 A1/B1）→ 点亮后跑 MEMTEST 验证闭环。

> 批量上架"点不亮"常是内存型号/批次不一致或插法未按通道对称，先核对 SPD 与插槽图更快。

## 第 4 章 数据中心基础设施

### 4.1 核心参数五大维度

| 维度 | 关键参数 |
| :-- | :-- |
| 基础设施与可靠性 | **Tier I~IV**（国内 GB 50174 的 C~A 级）；Tier IV/A 级容错最高，年可用性 **99.995%**（停机 ≤26 分钟）；冗余 N / N+1 / 2N / 2(N+1)；单机柜功率密度传统 4~8kW，AI 高密柜 20~100kW+ |
| 能耗与制冷 | **PUE = 总能耗 / IT 设备能耗**，越接近 1.0 越节能，新建大型要求 ≤1.25；**WUE = 年耗水量 / IT 能耗**（L/kWh）；制冷方式：风冷/水冷/液冷（冷板、浸没） |
| 算力与存储 | 通用算力看 vCPU 核数；HPC/AI 看 **FLOPS**（PFLOPS/EFLOPS）；存储看容量（TB/PB/EB）、**IOPS**、延迟 |
| 网络 | 出口带宽（Gbps/Tbps）+ **BGP 多线**；内部 **Spine-Leaf（叶脊）**，东西向 100G/400G/800G，微秒级延迟 |
| 环境与安全合规 | 冷通道 18~27℃、湿度 20%~80%（ASHRAE）；抗震 7~8 级；**VESDA** 极早期烟雾探测、七氟丙烷/IG541 气体灭火；ISO 27001、SOC 2、PCI-DSS、等保三级/四级 |

### 4.2 叶脊架构（Spine-Leaf）

- **一句话**：两层扁平拓扑，每个 Leaf 连每个 Spine，任意两点间提供多条等长、无环、极低延迟路径。
- **本质**：为云数据中心"东西向流量"爆发设计的**全互通高速公路网**。传统三层（接入-汇聚-核心）南北向流量层层上交易堵；叶脊中 **Leaf 接服务器、Spine 只转发**，任意两服务器通信固定 **2 跳（Leaf→Spine→Leaf）**。
- **四特征**：扁平化固定延迟、高带宽无收敛（1:1）、高可用全互联（坏一台自动绕行）、弹性扩展 Scale-out（加 Spine 即可）。
- **两机制**：①**路由代替交换**——Underlay 跑三层路由（OSPF/BGP），所有链路活跃，不用 STP 阻塞；②**ECMP**——哈希（源/目的 IP、端口）把流量分摊到多条上行链路。
- **运维关注**：不再查 MAC 表，而是 `show ip bgp summary` 看路由邻居；通信拥塞多半是 **ECMP 哈希极化**，调整哈希因子。TOR（柜顶交换机）就是典型 Leaf。

### 4.3 数据中心四大分区

| 分区 | 内容 | 角色 |
| :-- | :-- | :-- |
| **主机房** | 服务器机房、网络机房、存储机房 | 核心生产区（限制区） |
| **支持区** | 变配电室、柴发房、电池室、空调机房、UPS 用房、消防设施 | 动力与环境保障区 |
| **辅助区** | 进线间、总控中心、测试机房、备件库、维修室 | 运维操作与技术支持区 |
| **行政管理区** | 办公室、门厅、值班室、用户工作室 | 人员办公与客户接入区 |

> 灾备数据中心还额外划分**限制区、普通区、专用区**。底层逻辑是**风险隔离与效率优化**（把噪声大、振动强、有火灾风险的动力设施移出主机房）。

### 4.4 综合布线七大子系统（GB 50311）

记忆法：**"工水垂管设进建"** —— 工作区、水平、垂直（干线）、管理间、设备间、进线间、建筑群。

- **终端接入类**：工作区子系统（信息插座到终端的跳线）。
- **内部传输类**：水平子系统（楼层配线架到信息插座，永久链路 ≤90m）、垂直/干线子系统（楼层配线架到设备间主配线架）、管理间子系统（配线架/跳线/标签集合点）。
- **核心与外部类**：设备间子系统（核心网络设备、主配线架 BD）、进线间子系统（外部缆线引入）、建筑群子系统（园区内不同建筑的室外缆线）。
- 机制："跳线-配线架-缆线"逐级汇聚；"跳线变更"通常只在管理间配线架调整，不动永久链路。

### 4.5 供电架构

- **本质**：用多重冗余消除单点故障。类比 F1 赛车燃油系统（主油箱市电 + 备用油箱柴发 + 缓冲泵 UPS + 双油管 A/B 路）。
- **关键特征**：2N 或 N+1 冗余；服务器双电源分别接物理隔离的 A/B 路；市电断后 UPS 毫秒级零延迟接管，柴发启动并机；强弱电分离、电池室与主机房分离。
- **电能路径**：双路 10kV 市电 → 高压柜 → 变压器降为 380V/400V → UPS（交-直-交双转换净化）→ 配电柜 → 列头柜（RPP）→ 机柜 PDU → 服务器。
- **Tier 等级**：Tier I/II（N+1，有单点故障，99.741% 起）；**Tier III 可并发维护**（双路一主一备或均分，维护不停机）；**Tier IV 容错**（纯 2N 甚至 2(N+1)，物理隔离，99.995%+）。
- **巡检要点**：双电源服务器 PSU1/PSU2 必须分别插不同 PDU（A 路 UPS A 组、B 路 UPS B 组）；BMC 日志不能有 `PSU lost`；发现单电源运行等同"裸奔"立即恢复。

### 4.6 DCIM 与 BMS

**DCIM（数据中心基础设施管理）**
- 一句话：融合软件/硬件/传感器的综合管理平台，统一监控物理设施（供配电、制冷）与 IT 资源（服务器、网络），打破"IT 设备"与"机房设施"孤岛。
- 本质：数据中心的**数字孪生大脑**（全身 CT + 3D 数字模型）。
- 特征：物理与 IT 融合、全生命周期管理、3D 可视化、容量与能效（PUE）分析。
- 机制：**采集（SNMP/Modbus）→ 模型关联（服务器在哪柜哪 U 位、哪路 PDU）→ 分析优化（PUE/告警收敛）→ 联动控制（自动调空调）**。
- 价值：告警精准定位（从"服务器离线"缩到"A 列 03 柜 B 路 PDU 进线异常"）、容量规划、PUE 优化。

**BMS（两种含义）**

| 对比 | 楼宇管理系统 Building Management System | 电池管理系统 Battery Management System |
| :-- | :-- | :-- |
| 管理对象 | 冷水机组、空调、水泵、照明等机电设备 | UPS 后备电池组（铅酸/锂电） |
| 核心使命 | 保障 IT 环境温湿度、洁净度、空气流动 | 保障市电中断时后备电源可靠安全顶上 |
| 关键指标 | 送风温度、回风湿度、冷冻水流量、压差 | 电池内阻、单体电压、SOH、热失控风险 |
| 典型协议 | BACnet、Modbus | 厂商私有/UPS 专用接口 |
| 运维焦点 | 制冷效率（PUE）、设备轮换、环境告警 | 电池劣化预警、定期核容放电、火灾防护 |

> 三层架构（楼宇 BMS）：现场层（传感器/执行器）→ 自动化层（PLC/DDC）→ 管理层（BMS 服务器）。遵循"感知-分析-执行"闭环。锂电池热失控仅几秒预警，铅酸较长。

## 第 5 章 硬件知识

### 5.1 CPU

**关键参数（木桶效应：核数 × 单核性能 × 内存/IO 是否喂得饱）**

| 参数 | 含义/要点 |
| :-- | :-- |
| 核心/线程 | 线程数常=核心×2（SMT/超线程，BIOS 可开关） |
| 主频 Base / 睿频 Turbo | 睿频不能长时间维持，受功耗温度限制 |
| TDP | 热设计功耗，决定散热与机柜供电预算 |
| 缓存 L1/L2/L3 | L3 越大对数据库越有利；L1/L2 每核独占，L3 全核共享 |
| 制程 | 越先进同功耗性能/能效越好 |
| 内存通道 | 服务器 8~12 通道，**必须均衡插满** |
| PCIe 通道 | GPU/高速网卡多时尤其重要 |
| 互连 | Intel UPI / AMD Infinity Fabric，决定多路通信与 NUMA 延迟 |
| 路数 | 1S/2S/4S/8S；带 `U` 后缀单路 SKU 不能当双路用 |

**Intel Xeon 命名口诀**：**第一位看等级、第二位看代数、后两位看 SKU**。等级：8/9 铂金、6/5 金牌、4 银牌、3 铜牌（等级是定位不是性能绝对值，跨代金牌可能反超上一代铂金）。
- 后缀：H 数据库/4-8 路、Y SST-PP、N 网络/NFV、T 长生命周期/电信级、M/L 大内存、U 单路专用、V 虚拟机密度、S 存储、+ 集成加速器。
- 代际：1/2 代 LGA3647/6 通道 DDR4/PCIe3；3 代 LGA4189/8 通道 DDR4/PCIe4；4/5 代 LGA4677/8 通道 DDR5/PCIe5（**4/5 代同插槽刷固件可兼容**）；Xeon 6 LGA7529/4710。
- 典型：Gold 6338 = 金牌、3 代 Ice Lake、32 核 64 线程、48MB L3、205W、8 通道 DDR4-3200、64 条 PCIe4.0。

**AMD EPYC**：第一位代际（7=7003 Milan，9=9004 Genoa/9005 Turin），后三位 SKU；后缀 X 高频、P 高吞吐、B 双路、F 单路、H 液冷。片式（Chiplet）设计，单路 128~160 条 PCIe5.0，9004/9005 为 **12 通道 DDR5**，3D V-Cache 超大 L3。高核数适合云/虚拟化；**按单核授权的软件（如 Oracle）反而选核少高频型号**。

**国产信创**：海光 C86（x86 授权兼容，迁移成本几乎为零，内置国密 CCP/CSV3）、鲲鹏/飞腾（ARM64）、龙芯（LoongArch 自主）、兆芯（x86 授权）。海光四号 C86-4G：DDR5+PCIe5，最高 64 核 128 线程。**国产机型 BMC 界面/SEL 字段/BIOS 路径与 x86 不同，不要照搬经验**。

**缓存**：基于局部性原理（时间+空间），SRAM 制造，L1 最快最小逐核独占、L2 逐核独占、L3 最大同 CPU 共享。`lscpu` 可看 L1d/L1i/L2/L3。

**CPU 内存通道**：每通道 64bit 数据总线；单通道带宽 = 速率(MT/s)×8÷1000（DDR5-4800 约 38.4GB/s，8 通道约 307GB/s）。**交错（Interleaving）只能在容量相同的通道间形成**；插 6 条（8 通道平台）能点亮但性能打折，最优 8/16 条。同通道优先插物理距离 CPU 最远的槽（编号 0）。NUMA：本地访问 60~100ns，跨路 200~300ns（最高 3 倍惩罚）。

**异构运算**：CPU（总指挥，逻辑控制）+ GPU/NPU/FPGA/ASIC（加速器，并行矩阵运算），通过 PCIe/NVLink 互联，CPU 把任务 Offload 给加速器。AI 服务器巡检重点看 GPU 温度/显存/功耗（nvidia-smi），PCIe 链路降速或 AER 错误是训练中断常见原因。

### 5.2 内存

**七类参数**：容量、代际、速率带宽、时序、组织（Rank/位宽）、可靠性（ECC）、电气。
- **带宽公式（必背）**：单通道带宽(GB/s) = 速率(MT/s) × 8 ÷ 1000；整机 = 单通道 × 通道数（需对称插满）。例：DDR4-3200 单通道 25.6GB/s，8 通道 204.8GB/s；DDR5-5600 单通道 44.8GB/s，12 通道约 537.6GB/s。
- **DDR4 vs DDR5**：DDR4 1.2V、1 个 64-bit 通道、系统级 ECC；DDR5 1.1V（PMIC 上条）、**2 个独立 32-bit 子通道**、On-die ECC+系统级 ECC 双层、防呆口位置不同物理互斥。**代际由 CPU/主板决定，不能混插**。On-die ECC 不能替代系统 ECC。
- **时序**：CL/tRCD/tRP/tRAS，单位周期数；绝对延迟(ns)=周期数÷频率(MHz)×1000，不能脱离频率比较。
- **物理形态**：UDIMM（PC 无缓冲）、**RDIMM（服务器主流，带寄存器）**、LRDIMM（减载，超大容量）、SO-DIMM（笔记本）、NVDIMM（断电写 Flash）。

**分类**：易失/非易失（断电丢否）；SRAM（触发器，做缓存）/DRAM（电容需刷新，做内存条）；服务器 ECC（标配，纠 1 位 CE 检 2 位 UE）vs 非 ECC；Rank 1R/2R/4R（越多容量越大但电气负载高可能降频）。

**内存故障四类根因**：接触不良（重插恢复）、内存条损坏（单根测试必失败）、插槽/通道故障（好条换该槽仍失败）、兼容性/安装错误（代际混插、未按插槽顺序、规格不一致）。

**ECC**：64 位数据 + 8 位校验（共 72bit），汉明码自动纠单比特、检双比特。SEL 中 CE（可纠正）/UE（不可纠正）告警是底层健康直接体现。**服务器绝不能用普通 PC 内存替代**。

**标签解读示例**：`MTA18ASF2G72PDZ-2G3B1IG` / `16GB 2RX8 PC4-2400T-RE1-11` = 美光 16GB DDR4-2400 RDIMM 双列 2Rx8（18 颗=72bit ECC，2400T=CL17）。扩容三原则：类型必须匹配（RDIMM）、规格尽量一致、遵循插槽优先级。

### 5.3 硬盘

**HDD**：机械式唱片机，盘片+磁头，寻道+旋转延迟 → 随机读写弱（IOPS 几十~几百）、怕震动、有噪音。S.M.A.R.T 预警。冷数据用 7200 RPM 大容量 SATA/SAS。
**SSD**：电子开关替代机械运动，无延迟高 IOPS，但有 P/E 寿命（FTL 磨损均衡/垃圾回收/写入放大，需 TRIM）。SLC→MLC→TLC（主流）→QLC。企业级看 TBW/DWPD。**SSD 健康看剩余寿命和已写入量，不是坏道**；SSD 常突然掉盘，更依赖 RAID/热备兜底。

**接口**：SATA（6Gbps，半双工，大容量 HDD/入门 SSD）、SAS（12~24Gbps，全双工，双端口冗余，企业级主力）、NVMe/U.2（走 PCIe，深度队列，极速热插拔）、M.2（系统盘/边缘）。

**RAID 级别（必背）**：

| 级别 | 最少盘 | 利用率 | 容错 | 要点 |
| :-- | :-- | :-- | :-- | :-- |
| RAID 0 | 2 | 100% | 无 | 条带化最快，任一盘坏全丢，仅临时/缓存 |
| RAID 1 | 2 | 50% | 镜像 | 读快可靠，系统盘常用 |
| RAID 5 | 3 | (N-1)/N | 坏 1 块 | 分布式校验，读快写慢重建慢；**4TB+ 大盘不推荐**（重建读海量数据易遇 URE 二次故障） |
| RAID 6 | 4 | (N-2)/N | 坏 2 块 | 双校验，大容量盘推荐 |
| RAID 10 | 4 | 50% | 多块（每组镜像坏 1） | 镜像+条带，性能+冗余，**企业核心数据库首选** |

> **RAID 10 优于 RAID 1**：RAID 1 无条带化，写受限于最慢盘；RAID 10 先镜像再条带，读写性能成倍提升，数据库 IOPS 远高于 RAID 1。**RAID 不是备份！** 防不了误删/病毒/勒索/阵列卡损坏。

**RAID 卡**：专用处理器+固件卸载 RAID 运算，板载写缓存（Write Back 回写快），靠 **BBU 电池/超级电容+Flash（CacheVault）** 掉电保护。缓存策略因电池告警从 Write Back 降为 Write Through 会导致"变慢而非宕机"——排查：`megacli -LDInfo -LALL -aALL | grep "Current Cache Policy"`；换件前必须 `megacli -AdpCacheFlush -aALL` 强制刷缓存，确认无重建任务。

**MBR**：磁盘第一扇区 512 字节 = 引导代码 446B + 分区表 DPT 64B + 结束标志 `55AA`(2B)。最多 **4 个主分区**、最大 **2TB**，配 Legacy BIOS。`fdisk -l` 显示 `Disk label type: dos` 即 MBR。突破 4 分区靠扩展分区+逻辑分区（EBR）。GPT 配 UEFI：128 分区、>2TB。

**格式化不能彻底删数据**：只重建文件系统元数据（索引），不擦数据块，故可恢复。真删除是**覆盖**。安全擦除：机械盘 `shred` 多次覆写；SSD `hdparm`/`nvme format` 发 Secure Erase/Crypto Erase；终极物理销毁（消磁/砸盘）。

### 5.4 主板

**参数总览**：板型、芯片组（PCH）、CPU 插槽与路数、内存插槽/通道、PCIe 插槽、存储接口、板载网络、供电、BMC 芯片、安全（TPM 2.0/Secure Boot）。

- **板型**：ATX 305×244、Micro-ATX 244×244、Mini-ITX 170×170、**E-ATX 305×330（主流双路/GPU 服务器）**、SSI-EEB、刀片/定制板。
- **芯片组**：C621(1/2 代 LGA3647)、C621A/C627A(3 代 LGA4189)、C740 系列(4/5 代 LGA4677)。芯片组决定 PCIe/SATA/USB/网口数量。
- **插槽路数**：LGA3647(6 通道 DDR4)、LGA4189(8 通道 DDR4)、LGA4677(8 通道 DDR5)、SP3(EPYC 7002/7003)、SP5(9004/9005)。**看着能插未必兼容**（LGA3647 有 P/P+ 之分、3 代 Cooper Lake 与 Ice Lake 同 LGA4189 但不能互换），对照 QVL/兼容性矩阵。
- **供电**：24pin ATX + CPU 8pin（双路板 2 个）+ VRM 相数；双路两颗 CPU 的 8pin 必须都插满。
- **BMC 厂商命名**：浪潮 IPMI、华为 iBMC、惠普 iLO、华三 HDM、IBM IMM、戴尔 iDRAC。

**BMC（基板管理控制器）**：独立管理子系统，IPMI 硬件基础，嵌入式 SoC（芯片+固件），不依赖主机。
- 功能：远程开关机/重启/强制下电、KVM over IP、挂载虚拟光驱装系统、硬件监控（温度/风扇/电压/电源）、SEL 告警日志、BIOS 配置、SOL 串口重定向、用户权限审计、配置 RAID。
- 固件更新（高风险）：核对版本+读 Release Notes、备份配置/FRU/SEL、确认带内通道可用；**严禁断电或强制重启**；Web UI/命令行/OS 内工具三种方式；更新后验证版本/网络/传感器/SEL。

**BIOS**：上电最先运行的底层固件。
- 工作流程五阶段：**上电复位 → POST 自检 → 硬件初始化与资源分配 → 引导设备选择与加载 → 交接 OS**。
- 四核心作用：POST 自检、硬件初始化与资源分配、引导加载、提供配置接口（变更前记录、换板后恢复的基线）。
- 进 BIOS 快捷键：Dell F2、HPE F9/F10、Lenovo F1、华为/超聚变 Del 或 F4、浪潮 F2/Del/F12、H3C Del/F2、超微 Del、Cisco UCS F2。
- **UEFI vs Legacy**：UEFI 配 GPT（>2TB、128 分区、Secure Boot、.efi 文件、启动快）；Legacy 配 MBR（≤2TB、4 分区、无 Secure Boot、读第一扇区引导代码、16 位实模式）。CSM 是 UEFI 中的兼容层（开启会禁用 Secure Boot）。**启动模式与分区表强绑定，直接切换会导致系统无法引导**。Linux 查 `/sys/firmware/efi` 判断 UEFI 模式。

**总线**：按功能分数据/地址/控制总线；按方式分单工/半双工/全双工；按层次分片内/系统/IO/存储/现场总线；现代高速总线以串行（PCIe/USB/SATA）为主。
- **PCIe**：高速串行、点对点、全双工，Lane 聚合。Gen1~6 单 Lane 速率 2.5→5→8→16→32→64 GT/s；x16 单向带宽 Gen3≈15.8、Gen4≈31.5、Gen5≈63 GB/s。GPU/高速 NVMe 插 CPU 直连槽。
- **BDF 号**：`Bus:Device.Function`（如 `01:00.0`），PCIe 设备唯一"门牌号"，`lspci` 最左侧输出即 BDF。
- **QPI/UPI**：多路 CPU 间缓存一致性互连，NUMA 延迟差异的物理根源。UPI 取代 QPI（Skylake-SP 起）。SEL 中 `QPI/UPI Link Width Reduced` 表示降宽、`Connection Failed` 指向插槽针脚或 CPU 故障；`numactl --cpunodebind` 绑核避免跨路惩罚。

### 5.5 服务器

**按外形**：机架式（IDC 主流，1U/2U/4U）、塔式（灵活独立）、刀片（极限密度、共享机箱、厂商锁定）、高密度（双子星，1U/2U 塞多节点）、机柜式（整机柜一体）、边缘（深度约 450mm，适应非机房环境）。

**品牌型号**：浪潮 NF5180M5（1U 双路）、NF5280M5/M6（2U）、SA5212M5；华为 FusionServer 2288H V5/V6（2U）、1288H V5/V6（1U）；H3C UniServer R4900 G3/G5（2U）、R4700（1U）。
- 浪潮 NF5180M5 命名：NF=机架式，5=双路，1=1U，80=产品编号，M5=Intel 第 5 代平台（1/2 代至强可扩展）。

**x86 服务器**：CISC 架构（微指令翻译），开放标准、生态繁荣、Scale-out 强。多路用 UPI（Intel）/Infinity Fabric（AMD）+ NUMA，需绑核绑内存保证低延迟。

**指示灯（必背）**：
- 开机键：闪烁=待机，绿灯常亮=开机，黄灯常亮=故障。
- 电源灯：绿灯常亮=正常，黄灯常亮=报错，闪烁=待机。
- 硬盘灯：通电指示灯绿灯常亮=正常，不亮=硬盘/背板/盘架可能故障；另有状态指示灯。
- 位置定位灯：闪烁用于定位物理设备。

### 5.6 GPU / 电源 / 扩展板卡 / 机柜

**nvidia-smi（GPU 体检）**：
- 看概览：`Perf`（P0 最高、P12 最低，负载高但 Perf 低于 P2 说明被限频）、`Pwr:Usage/Cap`（贴 Cap 撞功耗墙）、`GPU-Util`（高不代表健康）、`Memory-Usage`、`Uncorr. ECC`（非零红旗）。
- 持续监控：`watch -n 2 nvidia-smi` 或 `nvidia-smi -l 2`；只盯一卡 `nvidia-smi -L` 后用 `-i UUID`（序号重启会变，推荐 UUID）。
- 模块查询 `-q -d TEMPERATURE/POWER/ECC/MEMORY`；温度持续 >85℃ 降频风险，HBM >75℃ 错误率上升。
- 故障排查：ECC 看 Volatile/Aggregate 的 Uncorrectable；PCIe 链路 `nvidia-smi -q | grep -A 10 "PCIe"` 看 Link Width/Gen；XID 错误 `dmesg | grep -i Xid`（**XID 79 掉卡、48 ECC 相关、54 供电线未插好**）；NVLink `nvidia-smi nvlink --status`（inactive 则多卡通信失效）。
- 管理（需 root）：`-pl` 功耗限制、`-c 1/0` 独占/默认模式、`-pm 1` 持久模式。
- **一句话**：利用率 100% 不是健康指标，Perf 降级、ECC 增长、PCIe 链路缩水才是优先处置信号。

**1+1 电源冗余**：两个相同电源模块（1 主 1 备），物理电气独立、分接 A/B 路 PDU，热插拔，毫秒级无缝切换。主备模式（Active-Standby）或均流模式（Active-Active，主流，各担 50%，故障另一路瞬间升 100%）。BMC 报 `Power Supply Failure` 时做好防静电直接换，业务无感。

**Riser 卡（转接卡）**：无源 PCB 转接板，把 PCIe 插槽从垂直转水平，让全高/双宽 GPU 能装入 1U/2U；一个 x16 可拆成两个 x8。无源（信号直通）vs 有源（含 PCIe Switch，做拆分 Bifurcation）。**型号严格匹配、互不通用**；GPU 必须装支持 x16 的槽，用自带 GPU 供电线；更换前记录线缆位置、完全下电、戴防静电腕带。

**OCP 卡（OCP NIC 3.0）**：开放计算项目的标准化夹层网卡，前维护/热插拔、免开盖，释放 PCIe 插槽给 GPU/NVMe，优化气流。SFF/LFF 尺寸，PCIe Gen5 x16，25G~400GbE。**并非所有 OCP 卡都支持热插拔**；有时作 BMC 共享管理网口，规划带外时注意端口映射。

**机柜**：IDC 标准柜 **42U 高、600mm 宽、1200mm 深**（宽度也有 800mm，深度 1000/1100/1200mm）。理论装 21 台 2U；实际考虑交换机/配线架占位、散热维修隔 1U、PDU 供电功率，一般装 **12~14 台**。

## 第 6 章 网络知识

### 6.1 OSI 七层模型（口诀：物数网传会表应）

| 层 | 名称 | 功能 | IDC 对应 |
| :-- | :-- | :-- | :-- |
| 1 | 物理层 | 比特流、电气/光/接口标准 | 网线、光纤、光模块、布线 |
| 2 | 数据链路层 | 相邻节点传帧、MAC 寻址、差错检测 | 交换机、MAC、VLAN、STP、链路聚合 |
| 3 | 网络层 | 逻辑寻址和路由 | IP、路由器、三层交换机、ACL |
| 4 | 传输层 | 端到端、端口复用、可靠/不可靠 | TCP/UDP、端口、负载均衡、防火墙策略 |
| 5 | 会话层 | 建立/管理/终止会话 | 会话保持 |
| 6 | 表示层 | 格式转换、加密、压缩 | TLS/SSL、编码 |
| 7 | 应用层 | 面向用户应用服务 | HTTP/HTTPS、DNS、SSH、SMTP、API |

**分层排障**：完全不通→物理层（网线/光模块/端口灯）；同 VLAN 不通→二层；跨网段不通→三层（IP/网关/路由）；端口连不上→四层；网站/SSH/DNS 异常→七层。OSI 是理论模型，实际用 TCP/IP。

### 6.2 TCP/IP 模型

- **四层**（标准）：网络接口层、网际层、传输层、应用层。**五层**（教学）：物理层、数据链路层、网络层、传输层、应用层。
- 与 OSI 对应：应用/表示/会话→应用层；传输→传输层；网络→网际层；数据链路+物理→网络接口层。
- **封装**：HTTP 报文 → 加 TCP 头（段 Segment）→ 加 IP 头（包 Packet）→ 加以太网帧头/FCS（帧 Frame）→ 比特流。接收端反向解封装。
- **运维关注**：网络接口层（端口灯/光功率/LACP/VLAN/STP/MAC）；网际层（IP/网关/路由/ACL/ping/traceroute/MTU）；传输层（端口监听/连接状态/防火墙/重传）；应用层（服务/DNS/证书/日志）。

**TCP vs UDP**

| | TCP | UDP |
| :-- | :-- | :-- |
| 连接 | 面向连接（三次握手/四次挥手） | 无连接 |
| 可靠性 | 可靠（序列号/ACK/超时重传/流控/拥塞控制） | 不可靠、尽力而为 |
| 传输单位 | 面向字节流 | 面向报文（保留边界） |
| 头部 | ≥20 字节 | 8 字节 |
| 通信 | 全双工、点对点 | 支持单播/组播/广播 |
| 应用 | HTTP/SSH/数据库/BGP(179) | DNS(53)/NTP(123)/SNMP(161/162)/VXLAN(4789) |

> 连接状态：LISTEN/ESTABLISHED/TIME_WAIT（主动关闭方产生，过多需内核优化）/CLOSE_WAIT（应用程序 bug，收到 FIN 未关闭）。拥塞算法 CUBIC/BBR。UDP 无状态，防火墙须放行双向；易被用于 DDoS 反射放大，需限速。

**ARP**：IPv4 中把 IP 解析为 MAC，**工作在二/三层之间**，报文直接作为以太网帧载荷（EtherType `0x0806`，28 字节）。机制：**先查缓存 → 广播请求（目的 MAC 全 F）→ 单播应答 → 更新缓存**（有老化时间）。Opcode 1=请求、2=应答。ARP 无认证 → **ARP 欺骗**（仿冒网关致断网/MITM、仿冒用户、泛洪）；防御：静态 ARP 绑定、交换机 ARP Detection/DAI。IPv6 用 NDP（NS/NA）替代。Linux 查 `ip neigh`/`arp -n`，Windows `arp -a`。
> 记：ARP 只工作在二层、只在局域网内有效、报文中没有源/目的 IP（指 ARP 载荷内）。

**NAT**：修改 IP 地址（私网→公网），缓解 IPv4 枯竭+隐藏拓扑。核心是五元组（源/目的 IP+端口+协议）改写与会话表（有状态）。**SNAT**（内网出网共享公网 IP）、**DNAT**（端口映射，公网→内网服务）、静态 NAT（一对一）、发夹 NAT（内网通过公网 IP 访问内部服务器）。破坏端到端透明性，需 ALG 配合。

### 6.3 路由

**分类**：IGP（AS 内部：OSPF、IS-IS、RIP、EIGRP）vs EGP（AS 之间：BGP）。按算法：距离矢量（RIP/EIGRP）、链路状态（OSPF/IS-IS）、路径矢量（BGP）。
- **选型**：IDC 内部中小用 OSPF、大型骨干用 IS-IS；出口/多线必用 BGP；小型用 RIP/静态路由。
- **度量 Metric**：同协议内选路，越小越优。RIP 看跳数（最大 15）；OSPF/IS-IS 看 Cost（参考带宽÷接口带宽）；EIGRP 复合度量（带宽+延迟）；BGP 看路径属性（AS-Path、Local Preference）。**AD 管理距离用于不同协议间选优（信谁），Metric 用于同协议内选路（走哪）**。

**静态路由**：手动配置，无协议开销、可控安全稳定，但不能自动适应拓扑变化。要素：目的网段/掩码、下一跳、出接口、优先级/AD（静态默认 AD 很小，如思科 1，优先级高于多数动态路由）。
- **默认路由** `0.0.0.0/0`（出口指向 ISP）；**浮动静态路由**（备份路由 AD 设大，主失效才激活）；**黑洞路由**（指向 Null0 丢弃，防环/封堵攻击）；主机路由 `/32`；汇总路由。
- 配置：华为 `ip route-static 192.168.10.0 255.255.255.0 10.0.0.2`；思科 `ip route ...`；Linux `ip route add ... via ... dev eth0`。
- 坑：下一跳不可达（路由在表但流量丢弃）、递归路由、默认路由掩盖明细缺失、多设备配置一致性。

**OSPF**：链路状态 IGP，"全网拼图、各自导航"。机制"**找邻居—传地图—算路由**"：Hello 建邻居 → 交换 LSA 同步 LSDB → SPF(Dijkstra) 算最短路径树。无环、分区域（Area 0 骨干）、触发更新组播（224.0.0.5/6）、以 Cost 为度量。OSPFv2(IPv4)/OSPFv3(IPv6)。排障看邻居是否 Full（卡 ExStart/Exchange 常是 MTU 不匹配或单向链路）。

**BFD**：双向转发检测，给链路装"独立高频心跳监测仪"，毫秒级（50/100ms）检测，协议无关，轻量。与 OSPF/BGP 联动：BFD 300ms 发现断链即通知 OSPF 瞬间切换，避免苦等 40 秒超时。异步模式/查询模式；单跳/多跳/Echo BFD。**BFD 回答"链路还活着吗"**。

**NQA**：网络质量分析，把手工 Ping 变成持续、可量化、可联动的探针，模拟 ICMP/TCP/HTTP/DNS/UDP 流量，测量时延、抖动、丢包率。与 **Track** 联动联动静态路由/VRRP 实现主备自动切换。**NQA 回答"链路好不好用"**（BFD 管快，NQA 管质量）。

### 6.4 以太网交换机

**以太网帧**：首部（目的 MAC+源 MAC+Type）+载荷+尾部 FCS（CRC-32 校验）。标准帧 64~1518 字节，MTU 1500。格式：Ethernet II（Type>0x0600，主流）、IEEE 802.3（Length≤0x05DC）、802.1Q（插 4 字节 VLAN Tag）。

**MAC 地址**：48bit（6 字节），前 24 位 OUI（厂商）、后 24 位厂商分配。单播（第一字节最低位 0）、组播（1）、广播（全 F）。交换机学习源 MAC 与端口对应关系生成 MAC 表，未知则泛洪。

**VLAN**：逻辑隔离广播域（802.1Q，VID 1~4094，4 字节 Tag 插在源 MAC 与类型字段间）。**Access 口**（接终端）：收无标签打 PVID、发剥离标签，只属一个 VLAN；**Trunk 口**（接交换机）：收发带标签（Native VLAN 除外），允许多个 VLAN。Hybrid（华为/华三）可手动配置带/不带标签。
- 排障：服务器不通先查 Access VLAN 对不对，跨交换机再查 Trunk 是否**放行该 VLAN**（漏放行最高频原因），两端 Native VLAN 必须一致。

**VXLAN**：L2 over L3 隧道封装，把原始以太网帧封装进 UDP（端口 4789），**24 位 VNI 支持约 1600 万虚拟网段**（解决 VLAN 4094 瓶颈），VTEP 负责封装/解封装（硬件/软件/混合模式）。跨三层网络保持二层连通。排障三层面：VTEP 可达性、VNI 映射一致性、Underlay 路由。

**生成树 STP（802.1D/w/s）**：二层防环，逻辑阻塞冗余链路构建无环树，防广播风暴（二层帧无 TTL）。BPDU 是通信语言。
- 三步：选**根桥**（桥 ID = 优先级+MAC，最小胜出）→ 选根端口/指定端口 → 阻塞其余端口。传统 STP 收敛 30~50 秒。
- 记忆：**802.1D 慢且单树（Delay/Default）；802.1w 快但单树（wait less，边缘端口+P/A 握手，秒级）；802.1s 快且多树可分担（share/split，MSTP 主流，多 VLAN 映射不同实例实现负载分担）**。
- 运维：根桥优先级手动设最低（如 4096）、接终端配边缘端口（PortFast）+ BPDU Guard、MAC 漂移常是 STP 未生效信号。

**虚拟交换机 vSwitch**：运行在 Hypervisor 上的纯软件二层交换机，连 vNIC 与上行物理网卡 pNIC，支持 VLAN 隔离、安全策略、链路聚合。VMware vSS/vDS、Open vSwitch(OVS)、FusionCompute。

**常见交换机**：华为 S5700/CE6800（数据中心常用）、H3C S9827；S1700/S6700 系列。

**华为交换机配置（速背）**：
```
system-view                      进入系统视图
sysname SW-Core-01               改设备名
vlan batch 10 20                 批量建 VLAN
interface g0/0/1 → port link-type access → port default vlan 10    接终端
interface g0/0/49 → port link-type trunk → port trunk allow-pass vlan 10 20   级联
interface Vlanif10 → ip address 192.168.10.1 24                   三层 SVI
ip route-static 10.0.0.0 24 192.168.1.2                          静态路由
ospf 1 router-id 1.1.1.1 → area 0 → network 10.0.0.0 0.0.0.255   OSPF（通配符掩码！）
interface Eth-Trunk 1 → mode lacp-static → 物理口 eth-trunk 1     链路聚合
save                             【必做】不保存重启全丢
display current-configuration / display vlan / display ip interface brief
```
> 三铁律：**save 才持久化**；**Trunk 必须显式放行 VLAN**；**对接服务器 bond4 时交换机 mode lacp-static 与服务器 mode=4 双向匹配**。Console 连接参数 9600/8/1/无/无（8N1），用专用 Console 线不能用普通网线。

**二层 vs 三层交换机**：二层基于 MAC 转发、整台一个广播域、不能 VLAN 间通信、接入口；三层基于 IP 转发、有路由表/ARP 表、可 VLAN 间路由（VLANIF/SVI）、支持路由协议、汇聚/核心层。三层交换机 ASIC 硬件加速适合内网高速跨网段；路由器软件转发为主、接口丰富、支持 NAT/VPN/防火墙适合出口。经典架构：接入二层 → 汇聚/核心三层 → 出口路由器/防火墙。

### 6.5 IEEE 802.1 与 SDN

**IEEE 802.1 三大族**：
- 防环：802.1D（STP，慢、单树）、802.1w（RSTP，快、单树）、802.1s（MSTP，快、多树可分担）。
- 隔离与优先级：802.1Q（VLAN 标签，TPID=0x8100，12 位 VID）、802.1ad（QinQ 双层标签，4094×4094）、802.1p（PCP 3 位 PCP 优先级 0~7，二层 QoS）。
- 接入控制：802.1X（EAPoL + RADIUS 认证，IDC 服务器 TOR 口通常不启用）。

**SDN**：转控分离 + 集中控制 + 开放可编程。三层两接口：应用层经**北向接口**（REST API）调控制器；控制层（SDN 控制器）经**南向接口**（OpenFlow/NETCONF）管设备，生成流表；数据层只做"匹配+动作"转发。类比：交警全部撤回指挥中心，路口只留红绿灯。形态：Underlay SDN（物理骨干）、Overlay SDN（VXLAN，云多租户主流，控制面在 OVS）。

### 6.6 网络不通标准排查链（七步）

`ip link`（网卡状态）→ `ethtool`（物理链路）→ `ip addr`（IP 掩码）→ `ip route`（网关）→ `ip neigh`（ARP）→ `ping 网关` → `ping 外网`。逐层定位，配合分层思想（物理→二层→三层→四层→七层）。

## 第 7 章 Linux 命令速背

> 总原则：**ip 管 IP/路由（临时）、ethtool 管网卡硬件、nmcli 管持久配置、ipmitool 管带外**。
> 学习优先级：第一梯队 top/df/ip/ethtool/ipmitool；第二梯队 lscpu/dmidecode/lspci/smartctl；第三梯队 mdadm/nmcli/lsscsi。

### 7.1 硬件与资产盘点

| 命令 | 必背要点 |
| :-- | :-- |
| **lspci** | 列 PCI/PCIe 设备；`-nn` 显示厂商/设备 ID（如 `[8086:10fb]`，8086=Intel）；`-vvv` 看 LnkSta 链路速率；`-t` 树状拓扑；`lspci -nnk` 看驱动。**看不到设备=硬件层（没插到位/槽禁用/BIOS 关），看得到设备但 ip link 看不到=驱动没加载或被 vfio 接管** |
| **lscpu** | 逻辑核 = Socket × Core/socket × Thread/core；**答物理几核用 Socket×Core，别把超线程算进去**；`Socket(s)=2` 是双路，`Thread(s)/core=2` 是开了超线程；`NUMA node(s)` 一颗 CPU 一节点；`-e` 看绑核拓扑、`-C` 看缓存、`--all` 看离线核 |
| **dmidecode** | 读 DMI/SMBIOS 静态固件信息（需 root）；`-t system` 看厂商/型号/SN/UUID（报修 SN）；`-t memory` 看每槽 Locator（如 DIMM A1）/容量/频率/PN；`-t baseboard` 主板；`-t bios` BIOS 版本；`-s system-serial-number` 只取 SN。**信息可被伪造，采购二手机器和机身铭牌/BMC 三方核对** |
| **lsscsi** | 列 SCSI/SAS/SATA 设备及盘符；`-s` 容量、`-g` 显示 /dev/sgX、`-t` 传输协议、`-H` 只看 HBA/RAID 卡。SCSI 地址 `[host:channel:id:lun]`。厂商 LSI/MegaRAID 多为 RAID 逻辑盘。**盘符重启会变，拔盘前用容量+SN+定位灯多重确认** |

### 7.2 磁盘与存储

| 命令 | 必背要点 |
| :-- | :-- |
| **lsblk** | 树状列块设备（盘→分区→LVM），无需 root 只读安全；`-f` 看文件系统/UUID、`-p` 完整路径、`-d` 只看裸盘、`-o` 自定义列。**MOUNTPOINT 为空=没挂载** |
| **fdisk** | 分区表操作（MBR，≤2TB）；`-l` 列出；交互键 `m/p/n/d/w/q`（**w 才写盘，危险**）；`Disk label type: dos`=MBR；`Boot *`=活动分区；Id 83=Linux、8e=LVM。改完 `mkfs` 报错需 `partprobe` 或重启刷内核分区表；>2TB 用 `parted`+gpt |
| **df** | 文件系统整体空间（读超级块，快）；`-h` 人类可读、`-T` 类型、`-i` inode、`-x tmpfs` 排除。经典坑：**删了大文件但 df 仍 100%** → 进程占用，用 `lsof \| grep deleted` 找进程重启。vs `du`：du 遍历目录算大小（慢） |
| **smartctl** | 硬盘 SMART 健康；`-a` 全部、`-H` 只看 PASSED/FAILED（**只看它不够**）、`-x` SSD/NVMe 寿命、`-t short/long` 自检、`-l selftest` 看结果。RAID 卡下用 `-d megaraid,0`。**重点盯 5 重映射/197 待映射/198 不可纠正 的 RAW_VALUE 是否为 0、是否增长**（Pre-fail 属性优先）。SMART 是预测非保证，RAID/备份才是根本 |
| **mdadm** | 软件 RAID；`cat /proc/mdstat`（`[UU]` 正常、`[U_]` 降级）；`mdadm -D` 详情；`--create` 【危险清空数据】；换盘：fail → remove → add，观察 rebuild。**RAID 不是备份**；降级尽快换盘；与硬件 RAID（storcli/megacli）区分 |

### 7.3 网络命令

| 命令 | 必背要点 |
| :-- | :-- |
| **ip** | `ip link` 看网卡（UP + LOWER_UP 才真通，NO-CARRIER=没插线）；`ip addr`/`ip a` 看 IP；`ip route` 看默认网关；`ip neigh` 看 ARP（FAILED 异常）；`ip addr add` 临时（重启丢）；`ip link set up/down`（down 业务网卡=断网）。**远程改 IP 前留带外后路+设定时回退** |
| **ethtool** | 网卡硬件层；`ethtool eth0` 看 Speed/Duplex/Port/Link detected（**no=物理层不通先查线/模块**）；`-i` 驱动/固件版本；`-S` 统计（rx_dropped/tx_errors/rx_crc_errors 看是否增长）；`-m` 光模块收发光功率（正常 Rx -3~-20dBm，-40 说明断纤/没发光/光口脏）；`-p` 闪灯定位；`-s` 强制改速率【危险，先确认对端+变更窗口】 |
| **nmcli** | NetworkManager 持久配置（重启不丢）；`device status` 看设备、`connection show` 看连接（device=硬件，connection=配置）；`con mod ... ipv4.method manual ipv4.addresses ... ipv4.gateway ... ipv4.dns ...` 改完要 `con up` 才生效；远程改配置防失联同上。**vs ip：ip 临时调试，nmcli 生产持久** |

**其他高频网络命令**：`ss -tlnp`（监听端口，替代 netstat）、`ping -c 4`、`traceroute`（Windows tracert）、`curl -I`、`nc -zv <ip> <port>`、`tcpdump -i eth0 host <ip>`。

### 7.4 带外管理与性能监控

| 命令 | 必背要点 |
| :-- | :-- |
| **ipmitool** | 带外 BMC 瑞士军刀。远程 `ipmitool -I lanplus -H <BMC_IP> -U <user> -P <pass> <子命令>`；本地 `ipmitool sensor list`。子命令：`power status`、`sensor list`（temp/fan/power）、**`sel list`（故障金矿，内存 CE/UE、电源掉电、温度告警）**、`chassis status`、`lan print 1`；`power on/off/reset/cycle`【危险，off 是硬断电，优先系统内 shutdown】。宕机排查流程：status → sensor → sel → reset。BMC 管理口与业务网是两套，管理网独立隔离 |
| **top** | 系统体检；`load average` 1/5/15 分钟（持续超核数=过载）；`%Cpu` 中 **wa(iowait) 高=磁盘瓶颈**（查 iostat 而非 CPU）；`buff/cache` 可回收看 available；快捷键 `1` 展开多核、`Shift+P` 按 CPU 排、`Shift+M` 按内存排、`q` 退出；`-b -n 1 > log` 批处理输出；`k` 杀进程【别乱杀 systemd/sshd】 |
| **free/uptime/vmstat/iostat** | `free -h` 看 available；`uptime` 看负载；`vmstat 1` 看 si/so（持续非零=内存不足）、wa；`iostat -xz 1` 看 %util（接近 100%=磁盘瓶颈） |

### 7.5 其他高频速查

| 类别 | 命令 |
| :-- | :-- |
| 文本三剑客 | `grep -i/-v/-E/-c`、`sed 's/old/new/g'`、`awk '{print $1}'`/`-F:`、`tail -f`（实时跟踪日志必备）、`find / -name "*.log" -mtime +7`、`wc -l` |
| 进程服务 | `ps -ef`/`ps aux`、`systemctl status/start/stop/restart/enable`、`kill -9 <PID>`、`killall java`、`nohup cmd &`、`crontab -e`（分 时 日 月 周 命令） |
| 用户权限日志 | `chmod +x`、`chown -R`、`sudo !!`、`journalctl -u sshd -f`、`dmesg -T`（内核日志/硬件报错/OOM）、`last/who` |
| 打包远程 | `tar -czf/-xzf`、`scp file user@ip:/path`、`ssh -p 2222 user@ip`、`ssh-keygen`/`ssh-copy-id` |
| 磁盘其他 | `du -sh`、`lsof \| grep deleted` / `lsof -i :80`、`mount/umount`、`dd`【数据毁灭者，写错 of= 毁盘】、`rsync -avz` |
