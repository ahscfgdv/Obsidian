你好！我是你的 Linux 命令行讲师。`df` 是我们在运维中最常敲的命令之一。和之前讲的 `fdisk` 不同，`df` 是一个**完全安全、只读**的命令，新手可以放心大胆地随便敲。

我们按照你的结构来学习：

---

### A. 一句话定义和适用场景

**`df`（Disk Free）是一个用于查看 Linux 系统中各个文件系统（挂载点）的磁盘空间使用情况的命令。**
**适用场景**：当你需要知道“系统盘是不是快满了”、“哪块数据盘还有剩余空间”、“某个目录挂在哪个分区上”时，第一反应就应该敲 `df`。

---

### B. 最常用的 5 个命令形式

#### 1. `df -h` 【只读/安全】
- `--human-readable`
*   **作用**：以人类可读的格式（Human-readable）显示磁盘空间。
*   **参数解释**：`-h` 会自动把字节换算成 K、M、G，比如把 `10485760` 变成 `10G`，这是最常用的形式。

#### 2. `df -T` 【只读/安全】
- `--print-type`
*   **作用**：在输出中增加一列“文件系统类型（Type）”。
*   **参数解释**：`-T` 代表 Type。能让你清楚看到这个分区是 `xfs`、`ext4` 还是 `tmpfs`。

#### 3. `df -i` 【只读/安全】
- `--inodes`
*   **作用**：查看 **Inode（索引节点）** 的使用情况，而不是磁盘容量。
*   **参数解释**：`-i` 代表 inode。在 Linux 中，每个文件都要占用一个 inode，如果磁盘还有空间，但 inode 耗尽（通常是因为小文件极多），也会报错“设备空间不足”。

#### 4. `df -h /var/log` 【只读/安全】
*   **作用**：查看指定目录所在的文件系统空间。
*   **参数解释**：加上路径，只显示该路径所在分区的使用情况，不用看满屏的输出。

#### 5. `df -x tmpfs` 【只读/安全】
*   **作用**：排除指定类型的文件系统。
*   **参数解释**：`-x` 代表 exclude（排除）。因为 `tmpfs` 是内存文件系统，很多时候我们只想看真正的物理硬盘（如 xfs/ext4），可以用 `df -h -x tmpfs -x devtmpfs` 过滤掉干扰项。

---

### C. “只读安全”示例：查看与解读输出

执行 `df -Th`：

```text
[root@localhost ~]# df -Th
Filesystem              Type      Size  Used Avail Use% Mounted on
/dev/mapper/centos-root xfs        37G  3.5G   34G  10% /
devtmpfs                devtmpfs  1.9G     0  1.9G   0% /dev
tmpfs                   tmpfs     1.9G     0  1.9G   0% /dev/shm
/dev/sda1               xfs      1014M  153M  862M  16% /boot
/dev/sdb1               xfs       5.0G   33M  5.0G   1% /data
```

**字段解析**：
*   **Filesystem**：文件系统设备名（通常是 LVM 逻辑卷或物理分区）。
*   **Type**：文件系统类型（如 xfs）。
*   **Size**：总容量。
*   **Used**：已用容量。
*   **Avail**：可用容量（普通用户可用）。
*   **Use%**：已用百分比。**通常达到 80%-90% 以上就该配置监控告警了。**
*   **Mounted on**：挂载点（也就是你访问数据的目录）。

### D. 运维高危大坑（df 本身安全，但结果会骗人）

`df` 没有任何破坏性，但它有一个极其经典的**“视觉欺骗”**场景，是面试和排障必考：

**场景**：你用 `df -h` 看到 `/` 盘用了 100%，然后你 `rm -rf` 删除了几个几十 GB 的日志文件。再次执行 `df -h`，发现使用率**依然是 100%！**

**原因**：在 Linux 中，如果一个文件被删除了，但还有进程（比如 Java 应用）正在打开（占用）它，`df` 会认为空间没有释放。
**排错**：用 `lsof | grep deleted` 找到占用该文件的进程，重启该进程，空间立刻释放。

---

### E. 常见误区与排错思路

1.  **把 `df` 和 `du` 搞混**：
    *   `df`（Disk Free）：看的是**文件系统的整体宏观空间**（超级块信息），速度快。
    *   `du`（Disk Usage）：看的是**具体目录下所有文件累加的大小**，需要遍历目录，速度慢。
2.  **误区：`df` 看到没满，但写不进文件**。
    *   **思路**：立刻执行 `df -i`，看是不是 Inode 满了（通常是因为存在几十万个碎小文件，如大量小日志或缓存）。
3.  **误区：目录被挂载覆盖了**。
    *   如果你在 `/data` 目录下存了文件，然后突然执行 `mount /dev/sdb1 /data`，原来 `/data` 下的文件会被“遮挡”隐藏。`df` 看到的是新挂载的 sdb1。

### F. 小练习（自己动手试试）
