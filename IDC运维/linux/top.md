你好！我是你的 Linux 命令行讲师。`top` 是 Linux 运维中最核心的“系统体检仪”。如果说 `df` 是看仓库还剩多少地，那么 `top` 就是看当前车间里的机器和工人有多累。

`top` 默认是一个动态刷新的界面，新手刚打开可能会觉得眼花缭乱，但掌握了核心指标，它就是你排障的最强武器。

---

### A. 一句话定义和适用场景

**`top` 是一个用于实时监控 Linux 系统整体性能（CPU、内存、负载）以及各个进程资源占用情况的交互式命令。**
**适用场景**：当业务方反馈“服务器卡顿”、“网站响应慢”，或者监控平台报警“CPU 使用率 100%”时，第一反应就是登录服务器敲 `top`，找出是哪个“捣蛋鬼”进程吃光了资源。

---

### B. 最常用的 5 个命令形式

#### 1. `top` 【只读/安全】
*   **作用**：以默认的 3 秒刷新率，动态显示系统全局状态和进程列表。
*   **参数解释**：无参数直接运行。按 `q` 键退出。

#### 2. `top -u <用户名>` 【只读/安全】
*   **作用**：只查看特定用户的进程。
*   **参数解释**：`-u` 代表 user。例如 `top -u mysql`，只看数据库的进程，过滤掉其他干扰。

#### 3. `top -p <PID>` 【只读/安全】
*   **作用**：只监控特定进程 ID（PID）的状态。
*   **参数解释**：`-p` 代表 pid。如果你已经知道某个进程可疑，可以用这个参数单独盯着它看。

#### 4. `top -d <秒数>` 【只读/安全】
*   **作用**：更改界面的刷新时间。
*   **参数解释**：`-d` 代表 delay。默认是 3 秒，例如 `top -d 1` 表示每秒刷新一次（排查高频抖动的性能问题很管用）。

#### 5. `top -b -n 1 > top_log.txt` 【只读/安全】
*   **作用**：将 `top` 的结果输出到文本文件中，而不是在屏幕上动态刷新。
*   **参数解释**：`-b` 代表 batch（批处理模式），`-n 1` 代表只刷新 1 次。常用于写脚本收集监控数据，或者保存现场证据。

### C. “只读安全”示例：读懂 top 的输出

执行 `top`，界面分为上下两部分：

**1. 顶部统计区（系统全局）**
*   **`load average: 0.00, 0.01, 0.05`**：系统负载（1分钟、5分钟、15分钟的平均值）。如果这个数值持续超过了你的 CPU 核心数，说明系统过载了。
*   **`%Cpu(s): 0.3 us, 0.3 sy, 98.9 id, 0.0 wa`**：
    *   `us`（user）：用户态占用。
    *   `sy`（system）：内核态占用。
    *   `id`（idle）：空闲率。
    *   **`wa`（iowait，IO等待）**：这个指标极其重要！如果 `wa` 很高（比如超过 30%），说明 CPU 没在干活，都在等硬盘读写，大概率是磁盘性能瓶颈。
*   **`KiB Mem` 和 `KiB Swap`**：物理内存和交换分区（虚拟内存）的使用情况。

**2. 进程列表区**
*   **`PID`**：进程 ID。
*   **`USER`**：运行该进程的用户。
*   **`%CPU`**：该进程占用 CPU 的百分比。
*   **`%MEM`**：该进程占用物理内存的百分比。
*   **`COMMAND`**：进程名称。

**💡 讲师提示：交互式快捷键**
在 `top` 界面中，你可以直接按键盘：
*   按 **`1`**：展开/折叠多核 CPU 的详细使用率。
*   按 **`Shift + P`**：让进程按 **CPU 占用率** 降序排列（最常用！）。
*   按 **`Shift + M`**：让进程按 **内存占用率** 降序排列。

### D. “危险操作”示例：在 top 中杀进程

🚨 **严重警告**：`top` 本身是只读的，但它在界面里隐藏了一个杀进程的功能。如果你误杀了系统核心进程（如 `systemd`、`sshd`、`mysqld`），会导致系统宕机或业务瞬间中断！

**危险操作流程**：
1.  在 `top` 运行界面，按 **`k`** 键（代表 kill）。
2.  屏幕上方提示 `PID to signal/kill:`，此时输入你想杀死的进程 PID（**千万别乱填**）。
3.  回车后，提示 `Send pid XXXX signal [15/sigterm]:`，默认是 15（优雅退出），直接回车。
4.  如果进程卡死，可能还会让你输入 `9`（强制杀死）。

**安全建议**：**不要**在 `top` 里练习杀进程！如果你真的需要终止进程，请退出 `top`，使用 `kill <PID>` 命令，这样你能更清楚地看到自己杀的是谁。

### E. 常见误区与排错思路

1.  **误区：只盯 CPU 100%，忽略了 `wa`（IO等待）**
    *   **排错**：如果你的业务卡顿，`top` 里 CPU 总占用不高，但 `wa` 飙到了 50% 甚至 80%，说明应用在疯狂读写磁盘，或者磁盘已经快坏了。此时应去查 `iostat`，而不是继续查 CPU。
2.  **误区：内存快满了，觉得系统要崩了**
    *   **排错**：Linux 有个“吃内存”的机制叫 `buff/cache`（缓存）。看着 `used` 很高，其实大部分是缓存，随时可以被释放。你应该重点看 `available`（可用内存）这一列。
3.  **误区：`load average` 很高，但 CPU 很闲**
    *   **排错**：负载（load）不仅算 CPU，还算处于“不可中断睡眠状态（D状态）”的进程。如果大量的进程卡在等待网络或硬盘 IO，CPU 很闲，但负载会爆表。此时需排查 IO 或 NFS 挂载问题。
